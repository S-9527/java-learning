# 00 · 程序是怎么跑起来的

> 状态：✅ 讲完了　·　最后更新：2026-10-12
> 代码：[`Hello.java`](../src/main/java/dev/javalearning/lesson00/Hello.java)

相信大家第一次写 Java 的时候，心里都会冒出一个疑问：**我写的这些英文，电脑到底是怎么看懂的？**
它又不像我们说话，打一个字它就能反应一个字。呃，电脑其实连一个字符都不认识——
你写的 `Hello`，在它眼里就是一堆高低电平。

这一课我们就把这件事从头到尾捋一遍：从你敲下的第一个字符，到屏幕上真的出现一行字，
中间到底发生了什么。搞清楚这个，后面所有的困惑——为什么要编译、什么是类、包为什么要放在
那么深的目录里——全都会顺理成章。

好，我们开始。

---

## 一、先看看你写的东西

我们先来写一个最经典的程序。呃，每一门语言的第一个程序好像都是它：

```java
package dev.javalearning.lesson00;

public class Hello {

    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
```

这个文件在 [`Hello.java`](../src/main/java/dev/javalearning/lesson00/Hello.java)，你可以打开对着看。
我们一行一行来，先不管每一行为什么必须这么写，那是后面课程的事，今天只关心它长什么样：

| 这一行 | 在干什么 |
|---|---|
| `package dev.javalearning.lesson00;` | 声明这个类"住在"哪个文件夹里 |
| `public class Hello {` | 声明一个类，名字叫 `Hello` |
| `public static void main(String[] args) {` | 程序的**入口**，程序从这里开始跑 |
| `System.out.println("Hello, Java!");` | 往屏幕上打印一行字 |
| 各个 `}` | 配对的花括号，一个开的一个关的 |

好，现在关键的问题就来了——**电脑能直接读这个文件吗？**

我们来试一下。呃，你不要真的去试，因为答案很显然：不能。你双击它没反应，
把它扔给操作系统，操作系统也不知道该拿它怎么办。
道理很简单：`public class Hello` 这串字符是**写给人看的**，CPU 只认识机器码，
也就是一串 0 和 1。中间必须有人做一次翻译。

在 Java 里，这个"翻译"分两步走，我们一步步来看。

## 二、正解：先编译，再运行

### 2.1 先认三个词：JDK、JRE、JVM

这三个词初学者一定会搞混，我们先用一个比喻记住它们，然后再看真实情况。

| 词 | 全称 | 管什么 | 比喻 |
|---|---|---|---|
| **JVM** | Java Virtual Machine | 真正"执行"字节码的那一个 | 翻译官 |
| **JRE** | Java Runtime Environment | JVM + 运行时要用的类库 | 舞台+道具 |
| **JDK** | Java Development Kit | JRE + 开发工具（`javac`、`javap`…） | 整套工具箱 |

你平时装的、用来写代码的，是 **JDK**——因为它里面已经包含了 JRE，JRE 里又包含着 JVM。
而真正让程序跑起来的，是 JVM。

我们来看一下本机装的是什么：

```terminal
$ java -version
openjdk version "25.0.4" 2026-07-21 LTS
OpenJDK Runtime Environment Zulu25.36+15-CA (build 25.0.4+7-LTS)
OpenJDK 64-Bit VM Zulu25.36+15-CA (build 25.0.4+7-LTS, mixed mode, sharing)
```

OK，`java` 是**运行**程序的命令，`javac` 是**编译**程序的命令。名字很像，别搞混：

```terminal
$ javac -version
javac 25.0.4
```

顺便说一句，这个 `c` 就是 compile 的那个 `c`。Java 里很多工具名都是这么来的，
看到名字就能猜个八九不离十。

### 2.2 第一步：编译

现在我们来编译刚才那个文件：

```terminal
$ cd src/main/java
$ javac -encoding UTF-8 -d out dev/javalearning/lesson00/Hello.java
$ ls -l out/dev/javalearning/lesson00/
total 4
-rw-r--r-- 1 anguish anguish 442 Oct 12 14:05 Hello.class
```

可以看到，编译完之后**什么都不会打印**。这是 Unix 工具的老传统：没消息就是好消息。
它只会在仓库里留下一个 `Hello.class` 文件。

那么这个 `-encoding UTF-8 -d out` 是什么意思？两个参数，我们各用一句话说清：

- `-encoding UTF-8`：告诉编译器"我的源码是 UTF-8 编码的"。这一课的笔记是中文的，
  不加这个参数在某些系统上中文会变成乱码，所以**以后编译一律带上它**
- `-d out`：把编译产物放到 `out` 目录里去，不要丢在源码旁边

好，接下来就是见证奇迹的时刻。我们来看看这个 `Hello.class` 文件里到底装了什么：

```terminal
$ head -c 32 out/dev/javalearning/lesson00/Hello.class | xxd
00000000: cafe babe 0000 0045 001d 0a00 0200 0307  .......E........
00000010: 0004 0c00 0500 0601 0010 6a61 7661 2f6c  ..........java/l
```

你可以看到开头四个字节是 `cafe babe`。这不是乱码，这是 Java class 文件的**魔数**——
每个 class 文件都以此开头，`cafe babe` 是"Java Baby"的意思，是当年 Sun 的程序员开的玩笑。
Java 虚拟机看到这四个字节，就知道"这是我的文件，我来处理"。

然后里面还能看到熟悉的字符：`6a 61 76 61 2f 6c` 对应的 ASCII 是 `java/l`——
说明 `java/lang` 这样的字符串确实是被原样存进去的。

那这到底是不是机器码呢？我们用一个叫 `javap` 的工具把它"反汇编"出来看看。
这个工具在 JDK 里，专门用来看 class 文件：

```terminal
$ javap -c -p -cp out dev.javalearning.lesson00.Hello
Compiled from "Hello.java"
public class dev.javalearning.lesson00.Hello {
  public dev.javalearning.lesson00.Hello();
    Code:
         0: aload_0
         1: invokespecial #1                  // Method java/lang/Object."<init>":()V
         4: return

  public static void main(java.lang.String[]);
    Code:
         0: getstatic     #7                  // Field java/lang/System.out:Ljava/io/PrintStream;
         3: ldc           #13                 // String Hello, Java!
         5: invokevirtual #15                 // Method java/io/PrintStream.println:(Ljava/lang/String;)V
         8: return
}
```

来，我们读一下 `main` 方法里的四行。感受一下它和 Java 源代码的差距：

```java
// 你写的
System.out.println("Hello, Java!");

// class 文件里存的（翻译成人话）
0: getstatic     System.out            // 找到 System.out 这个东西
3: ldc           "Hello, Java!"        // 把字符串常量压进来
5: invokevirtual PrintStream.println   // 调用 println 方法
8: return                              // 完事，返回
```

看出来了吗？**它一层都没简化。** 结构还在，`System.out` 还在，`println` 还在，
只是变成了一种更像汇编的中间形态。这就是 Java 的设计：

> 你写的 `.java` 先被编译成**字节码**（bytecode），存进 `.class` 文件；
> 字节码不针对任何具体平台，它交给 **JVM**；
> JVM 在运行时再把字节码转换成本台 CPU 能执行的机器码。

为什么要这么绕？直接编译成机器码不是更快吗？——
这正是 Java 当年最核心的卖点：**一次编写，到处运行**（Write Once, Run Anywhere）。
同一份 `.class`，Windows 上的 JVM、macOS 上的 JVM、Linux 上的 JVM 各自负责翻译，
你的代码不用为每个平台重写一遍。这是用一点性能换来的可移植性，而这个交易在大多数场景下非常划算。

### 2.3 第二步：运行

编译产物有了，现在跑起来：

```terminal
$ java -cp out dev.javalearning.lesson00.Hello
Hello, Java!
```

OK，出来了。我们来拆一下这条命令：

- `java`：启动 JVM
- `-cp out`：`classpath`，告诉 JVM"你要的类去 `out` 目录底下找"
- `dev.javalearning.lesson00.Hello`：程序的**全限定类名**，也就是"包名 + 类名"

这里就是初学者第一个大坑，我们专门来看一下。如果你偷懒，只写类名会发生什么：

```terminal
$ java -cp out Hello
Error: Could not find or load main class Hello
Caused by: java.lang.ClassNotFoundException: Hello
```

报错了。我们来读一下这个错误：`Could not find or load main class Hello`，
说"找不到名叫 Hello 的类"。可是 `Hello.class` 明明就在 `out/dev/javalearning/lesson00/` 底下啊？

原因就在 `package dev.javalearning.lesson00;` 那一行。**这个类的完整名字不是 `Hello`，
而是 `dev.javalearning.lesson00.Hello`。** 那句 package 声明相当于给类加了个姓——
你平时叫同事"小王"可以，但点名册上写的是"王建国"。

所以 JVM 找类的规则是这样的：把包名里的点换成目录分隔符，去 classpath 底下拼路径。
`dev.javalearning.lesson00.Hello` 就对应 `out/dev/javalearning/lesson00/Hello.class`。

这也解释了一个你早就该好奇的问题：**为什么源码要放在那么深的目录里？**

```
src/main/java/dev/javalearning/lesson00/Hello.java
                └────────────┬─────────────┘
                     package dev.javalearning.lesson00
```

目录结构和 package 声明必须一模一样。这不是谁定的无聊规矩，而是因为 Java 的规矩是
「文件放在哪」等于「类住在哪」，编译器和 JVM 都靠这个来定位类。
你把文件挪到别处，package 那一行不改，立刻就找不到类了。

### 2.4 一个偷懒但好用的办法

呃，讲了这么多"先编译再运行"，其实从 JDK 11 开始有个偷懒的办法：

```terminal
$ java dev/javalearning/lesson00/Hello.java
Hello, Java!
```

对，**直接把 `.java` 文件当参数传给 `java`**，它在内存里编译完立刻执行，
不生成 `.class` 文件。这在学基础、写小程序的时候非常方便，
本仓库 README 里主推的就是这种方式。

但请注意，这只是"源码启动模式"（source-file mode）的便利功能。
真正的工程里永远是「`javac` 编译出一堆 `.class`，然后打包、分发、部署」，
不会有人拿 `java Xxx.java` 上线。现在图省事可以，心里要清楚它不是正规流程。

## 三、第一次写代码一定会踩的坑

这一节是这一课最值钱的部分。我们直接来看错误长什么样——
**认得错误，比写对代码更重要**，因为你debug 的时间永远比写代码的时间长。

### 坑一：文件名和 public 类名不一致

仓库里有一个**故意写错**的文件：
[`Mismatch.java`](../src/main/java/dev/javalearning/lesson00/Mismatch.java)。
它里面声明的是 `public class Typo`——文件名是 Mismatch，类名叫 Typo。我们来编译它：

> 顺带说明：这个文件已经被 [`build.gradle.kts`](../build.gradle.kts) 排除出 Gradle 构建了，
> 否则 `./gradlew test` 会因为编译不过而失败。它只被 `javac` 单独调用来演示错误，
> 所以在 IDE 里看到它标红是**正常的**，那一课讲的就是这个错误。

```terminal
$ javac -encoding UTF-8 -d out dev/javalearning/lesson00/Mismatch.java
dev/javalearning/lesson00/Mismatch.java:9: error: class Typo is public, should be declared in a file named Typo.java
public class Typo {
       ^
1 error
```

我们读一下这条错误，它信息量很大，三个部分都要看：

| 位置 | 内容 |
|---|---|
| `Mismatch.java:9` | 哪个文件的第 9 行 |
| `error: class Typo is public, should be declared in a file named Typo.java` | 到底哪儿错了 |
| `public class Typo {` + 底下的 `^` | 把出错的那一行原样贴出来，`^` 指着出错的位置 |

规则很硬：**一个文件里只能有一个 `public class`，而且文件名必须和它一模一样。**
（没有 public 修饰的类不受此限，那是第 04 课的事，现在记住这条就够。）

所以你新建文件的时候，让 IDE 用类名当文件名，别反过来——顺序反了就会撞上这个错。

### 坑二：大小写

`hello`、`Hello`、`HELLO` 在 Java 里是三个完全不同的东西。类名首字母大写是惯例，
方法名首字母小写也是惯例——现在照着写就行，为什么这样是第 04 课的内容。

顺手说一句：**标识符不要用中文。** 虽然 Java 允许，但混在英文代码里会让读代码的人
（包括三个月后的你自己）非常难受，而且某些工具链对它支持并不好。

### 坑三：别忘了分号

Java 的每一条语句都要以分号结尾。漏一个，编译器就报错，而且报错的位置
**往往不是你真正漏分号的那一行**——它会往下指好几行。所以看到莫名其妙的语法错误时，
先往上翻几行看看是不是少了分号或者花括号。

## 四、这一课的术语表

我们今天提到的常用技术词汇有：

- **JDK**（Java Development Kit）—— 开发工具包，里面有编译器 `javac`、反汇编工具 `javap` 等
- **JRE**（Java Runtime Environment）—— 运行时环境，JVM 加上运行需要的类库
- **JVM**（Java Virtual Machine）—— Java 虚拟机，真正把字节码跑起来的那个
- **编译**（compile）—— 把 `.java` 源代码翻译成 `.class` 字节码
- **字节码**（bytecode）—— `.class` 文件里存的那种中间代码，不针对具体平台
- **机器码**（machine code）—— CPU 能直接执行的 0 和 1
- **类**（class）—— Java 代码的基本组织单位，一个文件里通常就一个 public 类
- **入口方法**（main method）—— `public static void main(String[] args)`，程序从这里开始
- **包**（package）—— 类的"姓"，决定类的全限定名和目录结构
- **全限定类名**（fully qualified class name）—— 包名加类名，比如 `dev.javalearning.lesson00.Hello`
- **classpath** —— 告诉 JVM 去哪些目录下找类的路径

## 五、下期再见

我们来总结一下。这一课我们弄明白了三件事：

1. **你写的代码 CPU 不认识**，中间必须编译。Java 的路径是
   `.java` →（`javac`）→ `.class` 字节码 →（JVM）→ 机器码
2. **为什么要这么绕**：为了"一次编写，到处运行"。同一份 `.class` 交给不同平台的 JVM 各自翻译
3. **文件名、public 类名、package、目录结构，四者必须对得上**，
   而且 JVM 找类用的是"包名 + 类名"的全限定名，不是光秃秃的类名

下一课我们进入 Java 的地基：**变量与类型**。
我们会看到"一个变量里到底装着什么"，以及为什么 `7 / 2` 在 Java 里等于 3 而不是 3.5——
那个答案会跟着你很久，因为它决定了你以后写除法的每一个瞬间。

谢谢观看，我们下期再见。
