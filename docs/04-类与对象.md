前三课我们一直在和"方法"打交道，所有代码都写在一个类里、用静态方法调用。
这一课要回答一个更根本的问题：**类到底是个什么东西。**

先给你结论，再验证它：

> **类（class）是一份说明书，对象（object）是按这份说明书造出来的每一件实物。**

就像"汽车设计图"和"停在车库里的那辆车"——图纸只有一份，车可以造一万辆，
每辆有自己的颜色、自己的里程表。

## 一、先让代码疼一次：两个对象，一份数据？

先看一段会让人愣住的代码：

```java
Person albert = new Person("Albert", 30);
Person neil = new Person("Neil", 25);
albert.birthday();      // albert 过生日，年龄加一

System.out.println(neil.age());   // 猜猜打印多少？
```

`neil` 的年龄会不会也跟着变？如果"类"是那个装数据的东西，那改了 albert 是不是就改了所有 Person？

我们来看真实输出：

```terminal
$ java src/main/java/dev/javalearning/basics/classes/ClassesDemo.java

albert = Person{name='Albert', age=30}

同一个人吗 → false

========== 2. 每个对象有自己的一份字段 ==========
albert.age() = 30，neil.age() = 25
给 albert 过完生日：
albert.age() = 31   ← 只有它变了
neil.age()   = 25   ← 另一个对象没被影响

========== 3. 字段是 private 的：外面只能通过方法碰 ==========
albert.name() = Albert

========== 4. static 字段：属于类，不属于任何对象 ==========

new 了 3 个之后：

  但每个对象有自己的 name：a / b / c
```

后面几节会反复引用这里的片段，所以先给全貌，再一节一节拆开。

**每个对象有自己的一份字段。** 这就是"实例"（instance）这个词的含义——
每 new 一次，就得到一个独立的实例，各自持有各自的数据。

## 二、正解：一个类的最小骨架

来看这一课的主角 [`Person.java`](../src/main/java/dev/javalearning/basics/classes/Person.java)，把它拆开看：

```java
public class Person {

    private final String name;      // 字段（field）：对象记住的数据
    private int age;                // 不加 final，说明它允许被改

    public Person(String name, int age) {   // 构造器：怎么造一个对象
        this.name = name;           // this. 前缀指字段，右边指参数
        this.age = age;
    }

    public String name() {          // 方法：对象能做的事
        return name;
    }

    public void birthday() {        // 改自己的字段
        age++;
    }
}
```

四样东西，各司其职：

| 组成 | 作用 | 类比 |
|---|---|---|
| 字段 field | 对象记住的状态 | 车的颜色、里程表 |
| 构造器 constructor | 规定"怎么造一个对象" | 出厂时必须装好什么 |
| 方法 method | 对象能做什么 | 车能开、能刹车 |
| `this` | 指"这个对象自己" | 司机说"我这辆车" |

### 2.1 字段：对象记住的数据

字段写在类里、方法外。它和局部变量（第 03 课讲过）的区别是：

| | 字段 field | 局部变量 local variable |
|---|---|---|
| 声明位置 | 类里、方法外 | 方法里 |
| 活多久 | 跟对象一样长 | 到花括号结束就没了 |
| 默认值 | 有（`0` / `null` / `false`） | **没有，不初始化不能用** |
| 每个对象 | 各有一份 | 每次调用方法各有一份 |

最后一条是重点。局部变量每次进方法都是新的，字段则是对象自带的。

### 2.2 构造器：对象的出生证明

构造器名字必须和类名一模一样，**没有返回类型**（连 `void` 都不写）：

```java
public Person(String name, int age) {   // ← 构造器
    this.name = name;
    this.age = age;
}
```

它是造对象的唯一正规入口。`new Person("Albert", 30)` 干的事就是：
按需分配内存 → 字段给默认值 → 执行构造器 → 返回地址。

#### 不写构造器会怎样？

编译器送你一个**无参的**，什么都不做：

```terminal
========== 5. 没写构造器时，编译器送你一个无参的 ==========
nc.count = 0（int 字段的默认值 0）
nc.text  = null（引用类型字段的默认值 null）
```

注意这两个默认值：`int` 是 `0`，引用类型是 `null`。这就是字段和局部变量的
另一个区别——**字段不初始化也有值，局部变量不初始化直接编译不过。**

#### 一旦写了构造器，编译器就不送了

这条规则坑过很多人。`Person` 写了 `Person(String, int)` 之后，
`new Person()` 就编译不过了：

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/basics/classes/broken/NoMatchingConstructor.java
src/main/java/dev/javalearning/basics/classes/broken/NoMatchingConstructor.java:17: error: constructor Person in class Person cannot be applied to given types;
        Person p = new Person();   // ← Person 只有 Person(String, int) 这一个构造器
                   ^
  required: String,int
  found:    no arguments
  reason: actual and formal argument lists differ in length
1 error
```

`required: String,int` / `found: no arguments`——错误说得很清楚。
**如果你需要无参版本，自己显式写一个**，别指望编译器猜。

### 2.3 `this`：同名的东西怎么区分

构造器里 `this.name = name` 是最容易看懵的一行。为什么不能写 `name = name`？

```java
public Person(String name, int age) {
    name = name;    // ← 这一行什么都没发生：参数自己赋值给自己
    age = age;
}
```

Java 的作用域规则是**内层遮盖外层**。方法参数 `name` 盖住了字段 `name`，
所以 `name = name` 是"参数自己给自己赋值"，字段压根没被碰到。

`this.name` 是显式说"我要的是**这个对象的字段**"，`name` 是"离我最近的那个变量"。

```
this.name  → 对象的字段（活得和对象一样长）
name       → 方法参数（活得和方法调用一样长）
```

`this` 还有别的用途（在构造器里调另一个构造器、方法链、传入自己），
但现在记住这一条就够：**同名时用 `this` 指字段。**

## 三、private：只留一扇门

`Person` 的字段全是 `private`。这意味着外面碰不到：

```java
albert.name = "x";   // 编译不过
```

真实错误长这样：

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/basics/classes/broken/ReachIntoPrivate.java
src/main/java/dev/javalearning/basics/classes/broken/ReachIntoPrivate.java:18: error: name has private access in Person
        System.out.println(albert.name);
                                 ^
1 error
```

那要读数据怎么办？**用类自己开的那扇门**：

```java
public String name() { return name; }
```

这叫**封装**（encapsulation），它的价值不是"为了私有而私有"：

1. **你能改内部实现，外面不用动。** 比如把 `name` 拆成 `firstName` + `lastName`，
   只要 `name()` 还返回拼接后的全名，调用方一行都不用改
2. **你能拦住非法的值。** 比如 `setAge(int age)` 里加一句 `if (age < 0) throw ...`，
   脏数据就进不来了
3. **你能让对象不可变。** `Person` 的 `name` 是 `final` 且没有 setter，
   所以它造好就不能改——这种对象天然线程安全（第 13 课会讲为什么）

第 3 条值得多说一句：`final` 字段不是"加了 private 就不能改"，而是**连这个类自己都不能改**。
所以 `Person` 没有 `setName` 方法——不是忘了写，是故意不给。

## 四、static：属于类，不属于对象

这是第 03 课就见过、但一直没解释的东西。现在说清楚。

```java
static int sharedCounter;   // 静态字段：属于类
int instanceCounter;        // 实例字段：属于对象
```

看真实对比：

```terminal
========== 4. static 字段：属于类，不属于任何对象 ==========
new 之前：instanceCounter = 0，sharedCounter = 0
new 了 3 个之后：
  通过对象 a 读 instanceCounter = 3（不推荐这么写）
  通过类名读 ClassesDemo.instanceCounter = 3
  三个对象看到的是同一个值吗 → true
  但每个对象有自己的 name：a / b / c
```

`instanceCounter` 造一个对象加一次，三个对象都读到 3——**它们读的是同一份数据**。
而 `name` 每个对象各有一份。

规则一句话：**静态成员跟着类走，类在它就在；实例成员跟着对象走，对象没了它就没了。**

三个推论：

1. **静态方法里不能直接访问实例字段**——因为它没有"这个对象"可用。
   `static` 方法里写 `name` 会编译不过，因为编译器不知道你要哪个对象的 `name`
2. **别用对象去访问静态成员**（`a.instanceCounter`）。能编译能运行，但读的人会以为
   "这是 a 自己的数据"。统一用类名：`ClassesDemo.instanceCounter`
3. **静态字段是共享的可变状态**——这是并发 bug 的主要来源之一，第 13 课的主角

顺带说清第 03 课预告过的那件事：**静态方法不参加多态。** 那是第 05 课的内容，
这里只记住一句：`static` 成员属于类，既然不属于任何对象，自然也就没有"不同对象不同行为"这回事。

## 五、toString 和 equals：Object 给每个类的遗产

Java 里所有类都直接或间接继承 `Object`，它送了每个类几个方法。
其中两个默认实现基本没法用，必须重写。

### 5.1 不重写 toString，打印出来是"身份证号"

```terminal
========== 7. 重写 toString：让打印出来的是人话 ==========
重写之后     → Person{name='Albert', age=31}
没重写的话是  → dev.javalearning.basics.classes.ClassesDemo$NoToString@5f8edcc5  ← 类名加 @ 加十六进制，日志里根本认不出是谁
```

那串 `@5f8edcc5` 是哈希码，人看不出任何信息。日志里刷一片这种东西，
排查问题时你会想把键盘吃了。

重写很简单：

```java
@Override
public String toString() {
    return "Person{name='" + name + "', age=" + age + "}";
}
```

`@Override` 不是必需的，但**建议总是写**——它让编译器帮你检查方法名有没有拼错。
拼错了没这个注解，编译器一声不吭地当成新方法，然后你花很久去查"为什么我写的
toString 不生效"。

### 5.2 不重写 equals，比的是"是不是同一个"

```terminal
========== 8. equals 不重写时比的是身份 ==========
内容完全一样 → Person{name='Albert', age=30}
albert == albertAgain       → false
albert.equals(albertAgain)  → false
同一个对象自己比             → true
```

两个内容完全一样的 `Person`，`equals` 竟然是 `false`。因为 `Object.equals`
的默认实现就是 `==`，比的是**身份**（是不是同一个对象），不是**内容**。

这和第 01 课 `==` 与 `equals` 是同一件事的两面——那时候讲的是 `String`，
现在讲的是你自己写的类。**规则不变：比内容就重写 `equals`。**

至于怎么重写对，那是第 05 课的内容（`equals` 和 `hashCode` 是契约，必须一起写）。

## 六、这一课的总表

| 写法 | 属于谁 | 怎么访问 | 每个对象 |
|---|---|---|---|
| 实例字段 `int age;` | 对象 | `p.age` | 各有一份 |
| 静态字段 `static int n;` | 类 | `ClassName.n` | 共享一份 |
| 实例方法 `void birthday()` | 对象 | `p.birthday()` | 各跑各的 |
| 静态方法 `static void main()` | 类 | `ClassName.main()` | 只有一份代码 |
| 构造器 `Person(...)` | 类（用来造对象） | `new Person(...)` | 每 new 一次跑一遍 |

判断方法就一句：**这个方法/字段需不需要知道"是哪个对象"？需要就是实例的，不需要就是静态的。**

`main` 是静态的，因为程序启动时还没有任何对象；
`birthday` 是实例的，因为它必须知道给哪个对象过生日。

## 七、不推荐的用法

- **别把所有字段都设成 public**。public 字段 = 把内部实现暴露出去，以后想改
  （比如 `age` 改成生日算年龄）就非得破坏所有调用方
- **别在构造器里干重活**（读文件、连网络、起线程）。构造器应该只负责把对象
  初始化到可用状态，重活交给显式的方法，让调用方决定什么时候做
- **别用对象访问静态成员**（`a.instanceCounter`）。语法允许，但误导读者
- **别重写 `toString` 时返回 null 或空字符串**。调试时你会感谢自己写了有用信息
- **别写"只存数据、没有行为的类"上瘾**。一个类只有字段和 getter/setter，
  没有自己的方法，通常意味着它该是别的类的一部分——当然，DTO 除外（那是另一回事）

## 八、这一课的术语表

- **类**（class）—— 一份说明书，定义了对象长什么样、能做什么
- **对象 / 实例**（object / instance）—— 按说明书造出来的实物；`new` 一次得一个
- **字段**（field）—— 对象记住的数据，也叫成员变量（member variable）
- **构造器**（constructor）—— 造对象的入口，名字必须和类名一样，没有返回类型
- **`this`** —— 指当前这个对象；同名时用来区分字段和参数
- **`static`** —— 静态成员，属于类而不属于对象，所有实例共享一份
- **封装**（encapsulation）—— 字段 private，只留方法当门；改内部不用惊动外面
- **`Object`** —— 所有类的老祖宗，`toString` / `equals` / `hashCode` 都从它来
- **重写**（override）—— 子类（这里是你的类之于 `Object`）换掉继承来的实现
