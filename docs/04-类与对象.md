# 04 · 类与对象

前三章的代码都是「一次性」的：写一个方法，调一次，就结束了。
从这一章开始，代码里出现了**可以长期存在的数据**——造出来一个对象，
存起来反复用。

于是多出一个问题：这些数据该由谁保管、谁能改动？答案就是类。

类做两件事：**把数据和操作数据的逻辑放在一起**，以及**规定谁能碰它们**。
这一章就围绕这两件事展开。

# 一、类型与实例：类是一份说明，对象是按说明造出来的每一件

```java
// src: src/main/java/dev/javaquest/basics/classes/Point.java
Point a = new Point(1, 2);
Point b = new Point(1, 2);
```

`Point` 是**类**（Java 术语叫类型），`a` 和 `b` 是两个**对象**（实例）。
类只描述「一个 Point 该有哪些数据、能做哪些事」，它自己不是数据。

同一个类可以造出任意多个对象，彼此独立：

```java
a.getX()   // 1
b.getX()   // 1
a == b     // false，是两个对象
```

### 两个内容相同的对象不相等

这里接着第 01 章那条线。`a` 和 `b` 存的坐标一样，但 Java 判断它们是否相等时，
先问的是「是不是同一个对象」。

```java
Point a = new Point(3, 4);
Point b = new Point(3, 4);

a.equals(b)   // false
```

`Point` 没有重写 `equals()`，所以走的是 `Object` 的默认实现——**比身份**。
想要「坐标相同就相等」，得自己重写 `equals()` 和 `hashCode()`（第 8 章会讲）。

同理，`toString()` 默认输出的是「全类名@哈希值」这种格式，调试时几乎不可读，
所以真实代码里都会重写它。

对应测试：同一个类可以造出很多个对象；没有重写 equals 时比的是身份；
toString 的默认格式。想看这三个现象，最快的办法是去跑
「同一个类可以造出很多个对象，它们互相独立」和「没有重写 equals 时，
比较的是身份而不是内容」这两条——它们和第 01 章的 `String` 那节正好对照。

# 二、状态与行为：字段存状态，方法操作状态

```java
// src: src/main/java/dev/javaquest/basics/classes/Point.java
public final class Point {
    private final int x;      // 字段：状态
    private final int y;

    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    public int getX() { return x; }             // 方法：行为

    public int distanceSquaredTo(Point other) { // 方法可以同时用到两个对象
        int dx = this.x - other.x;
        int dy = this.y - other.y;
        return dx * dx + dy * dy;
    }
}
```

**字段**回答「这个对象现在是什么样」，**方法**回答「它能做什么」。
把两者放进同一个类，是封装能成立的前提：数据和操作数据的逻辑待在一起，
外部就没法只拿走数据、绕过规则。

`distanceSquaredTo` 展示了方法能用上多少东西：既读自己的 `x`、`y`，
也读传进来的 `other` 的字段。

```java
new Point(0, 0).distanceSquaredTo(new Point(3, 4))   // 25，经典的 3-4-5 直角三角形
```

字段标成 `final` 之后，方法没法原地修改自己，只能返回一个改过的新对象：

```java
Point p = new Point(1, 2);
Point moved = p.withX(10);

p.getX()      // 1，原对象没动
moved.getX()  // 10
```

对应测试：字段存状态，方法读出来；方法可以同时用到自己的字段和别人的字段；
字段是 final 时方法返回一个改过的新对象。

# 三、构造器：怎么造出对象

构造器就是上面那段 `public Point(int x, int y)`。它的形状很特别：

```java
public Point(int x, int y) {   // 方法名和类名相同
    this.x = x;                // 没有返回类型，连 void 都不写
    this.y = y;
}
```

和普通方法的三个区别：**名字必须是类名**、**没有返回类型**、
**用 `new` 调用而不是直接调**。

### 这里必须写 this

构造器里 `x = x;` 是把**参数赋给自己**，字段从头到尾没被碰过：

```java
public Point(int x, int y) {
    this.x = x;    // 正确
    this.y = y;
}
```

写成 `x = x;` 也能编译通过，但两边的 `x` 都解析成形参，
结果是字段保持默认值 `0`。这是那种编译器和 IDE 都不吭声、只有结果不对的错。

为什么值得记住：`this.` 在方法里通常是可选的（`getX()` 里写 `x` 就行），
但在构造器这种「参数名和字段名相同」的场景里，它是唯一的区分手段。

这一节对应练习 5：构造器里写 `value = value` 而不是 `this.value = value`，
字段会拿到值吗？去跑它，里面放了一个正确写法和错误写法的对照。

### 一个类没写构造器会怎样

不是编译错误，而是**字段拿默认值**：

```java
// src: src/main/java/dev/javaquest/basics/classes/Bare.java
Bare b = new Bare();

b.number    // 0
b.flag      // false
b.text      // null
b.numbers   // null
```

规则是：`int` 一类的基本类型默认 `0`，`boolean` 默认 `false`，
其余（`String`、数组、其他对象）默认都是 `null`。

`null` 值得多说一句：它意味着「这个引用什么都没指向」。
所以 `b.numbers` 虽然能通过编译，访问它的 `length` 时就会抛
`NullPointerException`——在 `null` 上调用方法。

对应测试：构造器里的 `x = x` 是给参数赋值；一个类没写构造器时字段是默认值。
这一节对应练习 2（默认值）和练习 4（对 `null` 数组取 `length`）。

# 四、this：方法里怎么指回自己

`this` 指向**调用这个方法的那个对象**。

```java
Point p = new Point(3, 4);
p.distanceSquaredTo(new Point(0, 0));   // 这里 this 就是 p
```

`distanceSquaredTo` 内部同时读 `this.x` 和 `other.x`：前者是调用方 `p`，
后者是传进来的另一个对象。换个对象来调，`this` 就换成谁。

两处常见用法：

```java
// 1. 读自己的字段，写不写 this. 都能编译
public int getX() { return x; }
public int getX() { return this.x; }    // 两种都对

// 2. 区分同名的形参和字段——这时候 this. 是必需的
public void setX(int x) { this.x = x; }
```

`this` 不能出现在 `static` 方法里，因为静态方法没有「当前对象」可言。
`Counter.getCreated()` 这样的 static 方法从头到尾不需要 `this`。

对应测试：方法里的 this 指向调用它的那个对象。

# 五、static：属于类的东西和属于对象的东西

给成员加 `static`，它的归属就变了：

| | 实例成员 | `static` 成员 |
|---|---|---|
| 归属 | 每个对象一份 | 整个类一份 |
| 访问 | 通过对象访问 | 通过类名访问 |
| 能不能用 `this` | 能 | 不能 |
| 什么时候开始有值 | `new` 的时候 | 类初始化的时候（第一次用到这个类） |

用一个计数器看得最清楚：

```java
// src: src/main/java/dev/javaquest/basics/classes/Counter.java
public final class Counter {
    private static int created;   // 属于类，被所有实例共享
    private final int id;         // 属于对象，各有一份
    private int value;            // 属于对象，各有一份

    public Counter() {
        this.id = ++created;      // 编号接着往下排
    }

    public static int getCreated() { return created; }
}
```

造两个对象，它们共享 `created`，但各有自己的 `id` 和 `value`：

```java
Counter first = new Counter();    // id = 1
Counter second = new Counter();   // id = 2
Counter.getCreated();             // 2
```

这是第 01 章那句话的延续：`static` 字段装的是**一个值**，
而那个值的归属是**类**而不是任何具体对象。

对应测试：static 字段被所有实例共享；实例字段不共享；
static 方法通过类名调用。这一节对应练习 3：连续造两个 Counter，id 分别是多少。

# 六、可见性：谁能看见什么

前面所有示例里字段都写了 `private`。这是四档里最严的一档：

| 写法 | 同类 | 同包 | 子类 | 其他包 |
|---|---|---|---|---|
| `private` | ✅ | ❌ | ❌ | ❌ |
| 不写修饰符 | ✅ | ✅ | ❌ | ❌ |
| `protected` | ✅ | ✅ | ✅ | ❌ |
| `public` | ✅ | ✅ | ✅ | ✅ |

字段写成 `private` 之后，外部拿不到它本身，只能调用 `getX()`、`getY()`。
这层间接就是**封装**的起点：外部想改坐标，必须经过你定义的那个方法，
而你可以选择让它怎么改。

把字段标成 `final` 则更进一步——连方法内部都改不了它，
对象的对外表现就固定了下来。

这一节的完整对照表和 `protected` 的用法留到第 05 章（继承与多态），
那里会需要它。

对应测试：private 字段只能通过方法访问；字段用 final 时对象的对外表现也就固定了。

## 本章要点

- **类是说明，对象是按说明造出来的每一件。** 同一个类可以造很多对象、彼此独立，
  而 `equals` 默认比的是身份而不是内容
- 字段存状态，方法操作状态；两者放在一起、`private` 字段只从方法进出，
  才是封装
- **构造器没有返回类型，名字必须是类名**
- 形参与字段同名时 `this.` 是必需的：`x = x` 只是自赋值，字段还是 `0`；
  没写构造器也不报错，字段会拿默认值 `0` / `false` / `null`
- `static` 成员属于类（全类一份），实例成员属于对象（每个一份）；
  `this` 指向调用方，在 `static` 方法里不存在
