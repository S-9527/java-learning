# 01 · 变量与类型

上一课我们让一个程序跑起来了。这一课要解决一个更根本的问题——

**一个变量里，到底装着什么？**

这个问题听起来很蠢，但它是 Java 里最值钱的一个认识。你以后遇到的所有诡异现象：
`==` 有时候灵有时候不灵、`final` 好像锁不住东西、方法里改了参数外面居然没变、
算个钱末尾多出来一截——**全都能从这一课的答案推出来**。

我们先来看现象。

---

## 一、先让代码疼一次

[`VariablesDemo.java`](../src/main/java/dev/javalearning/basics/variables/VariablesDemo.java) 里放了六个互不相干的小实验。
我们直接跑：

```terminal
$ java src/main/java/dev/javalearning/basics/variables/VariablesDemo.java

========== 1. 整数：7 / 2 等于几 ==========
7 / 2    = 3
7 / 2.0  = 3.5
-7 / 2   = -3

========== 2. 溢出：给它最大值加一 ==========
Integer.MAX_VALUE = 2147483647
MAX_VALUE + 1     = -2147483648   ← 不报错，静默回绕

========== 3. 浮点：0.1 + 0.2 等于 0.3 吗 ==========
0.1 + 0.2            = 0.30000000000000004
0.1 + 0.2 == 0.3     = false
BigDecimal 的正确做法 = 0.3

========== 4. String：== 有时灵有时不灵 ==========
两个字面量 a == b          → true
字面量和 new 出来的 a == c → false
a.equals(c)                → true

========== 5. 装地址的变量：数组 ==========
改了 alias[0]，original[0] = 99   ← 跟着变了

========== 6. 装箱：== 在 Integer 上又是另一套 ==========
127 == 127 → true
128 == 128 → false
128 用 equals → true
```

来，我们一个个看。这些都是**真的跑出来的结果**，不是我编的：

- `7 / 2` 是 3，`0.1 + 0.2` 是 `0.30000000000000004`——**算错了**
- `MAX_VALUE + 1` 变成了负数，**而且不报错**
- 同样是"两个一样的字符串"，`a == b` 是 `true`，`a == c` 是 `false`——**`==` 到底在比什么**
- 我只改了 `alias`，`original` 却跟着变了——**两个变量是一个东西？**

如果你现在心里的感觉是"这些规则我得一条条背下来"，那这一课就是来救你的。
这些现象看起来毫无关系，其实背后是**同一件事**。

## 二、正解：盒子里装的是「值」，还是「地址」

变量就是一个盒子。关键是：**盒子里装的东西有两种**。

### 2.1 八种基本类型：装的是「值」本身

| 类别 | 类型 | 大小 |
|---|---|---|
| 整数 | `byte` | 1 字节 |
| | `short` | 2 字节 |
| | `int` | 4 字节 |
| | `long` | 8 字节 |
| 浮点 | `float` | 4 字节 |
| | `double` | 8 字节 |
| 字符 | `char` | 2 字节 |
| 布尔 | `boolean` | 规范未固定，实际通常 1 字节 |

这八种**装的就是值本身**。`int x = 7;` 执行完，那个盒子里踏踏实实躺着 `7`。
把 `x` 赋给 `y`，是**复制了一份值**过去，从此两家互不相干：

```java
int x = 7;
int y = x;      // y 里也躺着一个 7，但这是复制，不是共用一个盒子
x = 100;
System.out.println(y);   // 还是 7
```

这类盒子的问题是：**盒子大小是固定的**，装不下就会出事。这就是第一节里前两个现象的来源。

### 2.2 为什么 `7 / 2` 是 3

因为 `7` 和 `2` 都是 `int`，`/` 就按整数除法来算：**取商，余数直接丢掉**。
它不猜你想要小数，也不四舍五入。

```java
7 / 2       // 3    两个都是 int，结果是 int
7 / 2.0     // 3.5  除数是小数，7 被提升成 double
7.0 / 2     // 3.5  被除数是小数，2 被提升成 double
7 / (double) 2   // 3.5  显式转换，效果同上
```

想拿小数，让参与运算的**任意一边**是小数就行。

负数的规则是**向零截断**——把小数部分往零的方向抹掉：

```java
-7 / 2      // -3，不是 -4
```

这里顺带对比一下 Python：`-7 // 2` 是 `-4`（向负无穷取整）。
**只有处理负数时才会看出差别**，平时两种语言的直觉是一致的。

### 2.3 为什么 `MAX_VALUE + 1` 不报错

`int` 是 32 位，最大能装 `2147483647`。现在给它加一，装不下了，Java 怎么处理？

**它什么都不做，直接绕回去。**

```java
Integer.MAX_VALUE + 1   // -2147483648
```

不报错、不抛异常、不警告，静悄悄地变成最小值。这个行为的学名叫做
**回绕**（wraparound），二进制层面就是最高位溢出了，像汽车里程表从 99999 滚回 00000。

这件事的可怕之处在于：**它是个沉默的错误**。如果这是你的库存计数、订单号、用户余额，
它会一路错下去，而且你很难查——因为程序没崩，只是数字不对。

想要它报错，得主动说：

```java
Math.addExact(Integer.MAX_VALUE, 1)   // 抛 ArithmeticException: integer overflow
```

这一条断言在 [`VariablesTest.java`](../src/test/java/dev/javalearning/basics/variables/VariablesTest.java) 里，
`assertThatThrownBy` 就是"我期待的是一次抛异常"。你要是把它删掉 `@Disabled` 之外的部分跑一遍，
就能看到这个异常真的被抛出来。

更大的数怎么办？换成 `long`（8 字节，约 ±92 亿亿）。还嫌不够，还有 `BigInteger`——
它不固定大小，想要多大有多大，代价是比 `int` 慢。

### 2.4 比 int 小的类型：byte、short 的暗算

这两个最容易被忽视，因为大部分时候你都在用 `int`。但它们有个坑：

```java
byte a = 100;
byte b = 100;
byte sum = a + b;   // 编译不过
```

我们来看真实报错。我把这段写在了 [`ByteSum.java`](../src/main/java/dev/javalearning/basics/variables/broken/ByteSum.java)
里——它放在 `broken/` 包里，是**故意写错的**，已经被排除出 Gradle 构建，所以在 IDE 里看到它标红是正常的：

```terminal
$ javac -encoding UTF-8 -d out src/main/java/dev/javalearning/basics/variables/broken/ByteSum.java
src/main/java/dev/javalearning/basics/variables/broken/ByteSum.java:16: error: incompatible types: possible lossy conversion from int to byte
        byte sum = a + b;   // ← 就是这一行编译不过
                     ^
1 error
```

`incompatible types: possible lossy conversion from int to byte`——类型不兼容，
从 `int` 转 `byte` **可能丢失数据**。

规则是：**只要参与算术运算，`byte`、`short`、`char` 一律先提升成 `int`。**
所以 `a + b` 的类型已经是 `int` 了，再塞回 `byte` 就是"可能丢数据"，编译器拦住你。

想让它过，自己显式转，并且自己承担后果：

```java
byte sum = (byte) (a + b);   // 200 超出 byte 范围，会回绕成 -56
```

### 2.5 浮点：一个 `0.1` 引出的麻烦

现在看那个最经典的：`0.1 + 0.2` 为什么不是 `0.3`。

我们刨到底。`double` 是二进制浮点，它**只能精确表示那些能写成 2 的负整数次幂之和的数**。
`0.5` 可以（2⁻¹），`0.25` 可以（2⁻²），但 `0.1` 化成二进制是个无限循环小数：

```java
// 0.1 在 double 里实际存的值
new BigDecimal(0.1)
// 0.1000000000000000055511151231257827021181583404541015625
```

看这一长串。**你能见到的 `0.1`，从一开始就不是 0.1**，只是一个非常接近的近似值。
两个近似值相加，误差就露出来了：

```java
0.1 + 0.2                          // 0.30000000000000004
0.1 + 0.2 == 0.3                   // false
```

所以有两条铁律：

**铁律一：算钱、算精度敏感的东西，用 `BigDecimal`，而且必须用字符串那个构造器。**

```java
new BigDecimal("0.1").add(new BigDecimal("0.2"))   // 0.3    对
new BigDecimal(0.1).add(new BigDecimal(0.2))       // 0.3000000000000000055...  错
```

`new BigDecimal(0.1)` 会把 double 里那个近似值**原样带进来**，等于把误差洗白成了精确值，
比不用还坏。字符串构造器 `new BigDecimal("0.1")` 才是你脑子里那个十进制的 0.1。

**铁律二：不得不比两个浮点相等时，比差值，不比相等。**

```java
Math.abs(0.1 + 0.2 - 0.3) < 1e-9   // 工程上的写法
```

写 `1e-9` 这种阈值叫"容差"，具体多大看你的精度要求。这一条也写成了断言，在测试里跑着。

### 2.6 引用类型：装的是「地址」

除那八种之外，**其余一切变量装的都是地址**——数组、`String`、你自己写的类，全是。

`int[] original = {1, 2, 3};` 执行完，内存里有个数组，而 `original` 这个变量里装的是
**指向那个数组的地址**，不是数组本身。

于是这一节的第一个现象有了解释：

```java
int[] original = {1, 2, 3};
int[] alias = original;    // alias 里装的是同一个地址
alias[0] = 99;

System.out.println(original[0]);   // 99
```

`alias` 和 `original` 是**两个变量、一份数据**。就像两个人手里有同一个房间的钥匙，
你在房间里挪了家具，另一个人进来照样看得见。

这种关系的学名叫**别名**（aliasing）。测试里 `assertThat(alias).isSameAs(original)`
断言的正是"这两个引用指向同一个对象"。

**这就是第 03 课「为什么传进去改不了外面的变量」和第 05 课「深拷贝浅拷贝」的根。**
今天先记住这句话：装地址的变量，赋值是"给钥匙"，不是"复制房间"。

### 2.7 == 到底在比什么

现在回到那个 `a == b` 是 `true`、`a == c` 是 `false` 的怪事。

`==` 的核心语义从来没变过：**比两个盒子里装的东西一不一样。**

- 基本类型装值 → `==` 比的就是值，`7 == 7` 为 `true`
- 引用类型装地址 → `==` 比的是地址，也就是"是不是同一个对象"
- `String` 是引用类型，所以 `==` 比的也是地址

那 `a == b` 为什么是 `true`？因为**字符串常量池**：

```java
String a = "java";        // 池里存了一份 "java"，a 指向它
String b = "java";        // 池里已经有了，不重复存，b 也指向它
String c = new String("java");   // 强行 new 一个新的，c 指向另一个对象
```

两个写字面量 `"java"` 会共享同一个对象，所以地址相同；`new String(...)` 是明确要求
再造一个，所以地址不同。**内容一样，但不是同一个东西。**

想看内容一不一样，用 `equals`：

```java
a.equals(c)     // true  —— 这才是"内容相同"
```

所以规矩很简单：

| 你想比 | 用 | 别用 |
|---|---|---|
| 基本类型的值 | `==` | — |
| 两个引用是不是同一个对象 | `==` | — |
| 对象的内容一不一样 | `equals` | `==` |

反过来一句提醒：`equals` 是可以被重写的，`==` 永远重写不了。别人写的类如果不重写
`equals`，它就只能按 `==` 的语义来比身份——那是第 05 课的内容。

### 2.8 final 锁的是引用，不是内容

`final int[] locked = {1, 2, 3};` 之后：

```java
locked[0] = 99;              // 编译得过：引用没变，变的是盒子里那份数据
// locked = new int[3];      // 这一行才编译不过：想换一把钥匙，没门
```

所以 `final` 的正确理解是：**这个变量这辈子只能指向这一个对象**，
但它不保证那个对象自己不变。想让对象也改不动，得靠设计（比如用不可变类），不是靠 `final`。

### 2.9 装箱：两个世界之间的桥，也是雷

Java 有八种基本类型，也各有一个对应的"包装类"：`int` ↔ `Integer`、`double` ↔ `Double`……

写代码时它们能自动互相转换，这叫**自动装箱**和**自动拆箱**：

```java
Integer boxed = 127;     // 自动装箱：int → Integer
int unboxed = boxed;     // 自动拆箱：Integer → int
```

坑就在这个"自动"上：`Integer` 是引用类型，`==` 比的是地址。而 JDK 为了省内存，
**缓存了 -128 到 127 这两个**装箱对象：

```java
Integer i1 = 127, i2 = 127;   // 缓存命中，同一个对象
i1 == i2    // true

Integer j1 = 128, j2 = 128;   // 超出缓存，各自 new
j1 == j2    // false
j1.equals(j2)   // true  ← 想比内容就用这个
```

这个"有时 `true` 有时 `false`"的特性，坑过无数人。**规矩照旧：比内容一律 `equals`。**

自动装箱还有个更阴的坑：

```java
Integer boxed = null;
int unboxed = boxed;   // NullPointerException
```

`Integer` 可以为 `null`，但 `int` 不行。拆箱时发现是 `null`，直接炸。
这一条也写成了断言，跑一下你就看见它真的炸。

## 三、这一课的一张总表

把混乱的现象收进一张表，以后忘了就回来查：

| 现象 | 根因 | 怎么办 |
|---|---|---|
| `7 / 2 == 3` | `int` 之间只能整数除 | 随便让一边变小数 |
| `-7 / 2 == -3` | 向零截断，不是向下取整 | 记牢，别猜 |
| `MAX_VALUE + 1` 变负数 | `int` 32 位，溢出静默回绕 | `Math.addExact`，或换 `long`/`BigInteger` |
| `byte + byte` 编译不过 | 算术运算一律先提升成 `int` | 显式强转，自己负责 |
| `0.1 + 0.2 != 0.3` | 二进制存不下十进制的 0.1 | 算钱用 `BigDecimal("...")` |
| `a == b` / `a == c` 一真一假 | `==` 比地址；字面量走常量池 | 比内容用 `equals` |
| 改了 `alias`，`original` 跟着变 | 引用类型装地址，两个变量一份数据 | 想独立就复制（第 05 课细讲） |
| `final` 数组还能改内容 | `final` 锁引用不锁内容 | 想不可变得靠设计 |
| `127 == 127` 是 `true`，`128 == 128` 是 `false` | `Integer` 缓存 -128~127 | 一律 `equals` |
| `Integer` 拆箱炸 NPE | `null` 拆箱不成 `int` | 拆箱前判空 |

## 四、不推荐的用法

- **别用 `==` 比 `String`／`Integer`／任何对象的内容**，一律 `equals`
- **别用 `double`／`float` 算钱**，用 `BigDecimal`，而且**必须用字符串构造器**
- **别拿 `new BigDecimal(0.1)` 当"精确的 0.1"**，它比你想的更不准
- **别用 `int` 存可能溢出的计数**（订单号、库存、流水号），要么 `long`，要么先想清楚上限
- **别依赖 `char` 能存下所有字符**——它存的是 UTF-16 的一个代码单元，emoji 等辅助平面字符要两个 `char`
- **别为了省内存随手用 `byte`／`short`**，除非你真的在处理二进制协议或数组特别大；
  而且记住它们一参与运算就变 `int`

## 五、这一课的术语表

- **变量**（variable）—— 一个装数据的盒子
- **基本类型**（primitive type）—— 八种，装值本身
- **引用类型**（reference type）—— 装地址，指向真正的对象
- **类型提升**（type promotion）—— `byte`/`short`/`char` 一运算就先变 `int`
- **整数溢出**（integer overflow）—— 装不下就静默回绕
- **回绕**（wraparound）—— 溢出后从最大值滚回最小值
- **浮点精度**（floating-point precision）—— 二进制存不下某些十进制小数
- **BigDecimal** —— 十进制精确运算，算钱用它
- **容差**（tolerance）—— 比浮点相等时用的阈值，比如 `1e-9`
- **别名**（aliasing）—— 两个引用指向同一个对象
- **`==`** —— 比盒子里装的东西；引用类型比的是地址
- **`equals`** —— 比内容，可以被重写
- **字符串常量池**（string constant pool）—— 字面量共享的那片区域
- **自动装箱／拆箱**（autoboxing / unboxing）—— 基本类型与包装类之间自动转换
- **包装类**（wrapper class）—— `Integer`、`Double` 这些

## 六、下期再见

我们来总结一下。这一课的核心只有一句话：

> **变量是个盒子。八种基本类型里装的是值，其余一切装的都是地址。**

第一节课那六个诡异的实验——`7/2` 等于 3、`0.1+0.2` 不等于 0.3、`==` 时灵时不灵、
改了 `alias` 之后 `original` 跟着变、`127==127` 而 `128!=128`——现在全都有了解释，
而且它们是同一个原因的不同侧面。**记住这个，比记住那六条规则值钱得多。**

另外给自己留两句提醒：

1. **`==` 比的是盒子里的东西。** 拿不准的时候，问自己"我这次到底想比内容还是比身份"
2. **算钱立刻想到 `BigDecimal`。** 不是"以后注意"，是现在立刻

下一课我们讲**运算符与流程控制**：`if`、`switch`、`for`、`while`。
会看到 `&&` 为什么会"短路"——以及这个短路在什么情况下会变成一个隐蔽的 bug，
还有 Java 14 之后的 `switch` 怎么写才能让编译器帮你检查漏没漏写分支。

谢谢观看，我们下期再见。
