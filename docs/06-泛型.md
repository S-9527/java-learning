[继承与多态](./05-继承与多态.md)结尾留了个问题：

> 如果我想要一个"什么都能装的盒子"，怎么才能在编译期就知道装的是什么、取出时不用强转？

这一课就来回答它。而且答案可能和你想的不太一样——**泛型不是"让一个类能装所有类型"的语法糖，
它是把类型检查从运行期搬到编译期的工具。**

先看全貌，后面一节一节拆：

## 一、先让代码疼一次

需求很简单：**打印一个 Integer。**

于是写一个 `IntegerPrinter`：

```java
public class IntegerPrinter {
    private final Integer content;          // ← 字段类型是 Integer

    public IntegerPrinter(Integer content) {
        this.content = content;
    }

    public void print() {
        System.out.println(content);
    }
}
```

第二天需求来了：**打印一个 String。** 于是……再复制一个：

```java
public class StringPrinter {
    private final String content;           // ← 唯一的差别在这里

    public StringPrinter(String content) {
        this.content = content;
    }

    public void print() {
        System.out.println(content);
    }
}
```

两个类放在一起看：字段、构造器、方法体**一模一样**，只有类型不同。

```terminal
========== 1. 先让代码疼一次：每加一种类型就抄一个类 ==========
42
hello
两个类的代码一模一样，只有类型不同
再加一个 Double 呢？再加一个 Person 呢？
```

这就是**代码重复**（code duplication）。它的危害不只是"多写几行"：

- 要加一种类型，就得再抄一个类。一百种类型就是一百个类
- 逻辑一旦要改（比如加上日志），一百个类都得改一遍，漏一个就出事
- 而且**编译期什么都检查不出来**——`StringPrinter` 和 `IntegerPrinter` 之间
  没有任何关系，编译器不知道它们本该是同一件事

那么问题就来了：**能不能只写一个类，让类型本身变成一个"参数"？**

---

## 二、正解：泛型类 `Box<T>`

能。把那个"变化的类型"抽出来，写成尖括号里的占位符：

```java
public class Box<T> {

    private T content;                      // ← T 是占位符，不是具体类型

    public Box(T content) {
        this.content = content;
    }

    public T get() {
        return content;
    }

    public void set(T content) {
        this.content = content;
    }
}
```

`<T>` 里的 `T` 叫**类型参数**（type parameter）。它和方法的参数是一回事，
只是"值"换成了"类型"：

| | 普通参数 | 类型参数 |
|---|---|---|
| 写在哪儿 | `void print(String s)` | `class Box<T>` |
| 谁来决定 | 调用方传的**值** | 调用方传的**类型** |
| 什么时候定 | 运行期 | **编译期** |

`T` 只是个名字（叫 `E`、`Element`、`Whatever` 都行，`T` 是 Type 的惯例）。
具体是什么类型，由调用方在 `new` 的时候决定：

```java
Box<String> text = new Box<>("hello");     // 这里 T = String
Box<Integer> number = new Box<>(42);       // 这里 T = Integer
```

```terminal
========== 2. 泛型类：Box<T>，一份代码装所有类型 ==========
text.get()   = hello   ← 直接是 String
number.get() = 42   ← 直接是 Integer
String asString = text.get() → 不用强转：hello
int asInt = number.get()     → 不用强转，还自动拆箱了：43
T 由调用方决定：new Box<String> 和 new Box<Integer> 是同一个类的两种用法
```

注意最后一行：`new Box<String>` 和 `new Box<Integer>` **用的是同一个类**，
只是给了不同的类型实参。一个类，装下了所有类型——这正是第一节那两个 `Printer`
做不到的事。

顺便解释一下 `new Box<>(42)` 里那个空尖括号：这叫**钻石运算符**（diamond operator），
Java 7 起有。编译器从左边的 `Box<Integer>` 就能推出 `T` 是 `Integer`，
不用再写一遍 `new Box<Integer>(42)`。

### 2.1 变量类型和类型实参是两件事

`Box<String> text` 这个声明里有两个信息：

- `Box` —— 用哪个类
- `<String>` —— 这个盒子的 `T` 是 String

所以 `text.get()` 的返回类型**在编译期就是 String**，可以直接赋给 `String` 变量，
不用写 `(String) text.get()`。这就是泛型最直接的收益：**少一次强转，多一道编译期检查。**

## 三、类型参数不能用基本类型

写到这里，很多人会顺手试一下 `Box<int>`。**编译不过。**

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/generics/broken/PrimitiveTypeArgument.java
src/main/java/dev/javalearning/generics/broken/PrimitiveTypeArgument.java:20: error: unexpected type
        Box<int> box = new Box<>(42);   // ← int 不能当类型参数
            ^
  required: reference
  found:    int
1 error
```

**`unexpected type` / `required: reference` / `found: int`**——javac 的意思很直白：
这里要的是**引用类型**（reference type），`int` 不是。

原因是类型擦除（第八节会讲透）：运行期 `T` 会被擦成 `Object`，
而 `Object` 装不了基本类型，只能装引用。所以泛型的类型参数**必须**是引用类型。

那 `int` 怎么办？用**装箱类型**（wrapper type）`Integer`：

```java
Box<Integer> box = new Box<>(42);
int value = box.get();      // 自动拆箱，写起来和 Box<int> 几乎没差别
```

[变量与类型](./01-变量与类型.md)讲过的自动装箱/拆箱，在这里正好把不便之处抹平了。
八种基本类型各有各的装箱类型：`int`→`Integer`、`double`→`Double`、`boolean`→`Boolean`……
泛型里用它们就行。

（一个例外：`int[]` 是引用类型，所以 `Box<int[]>` 合法——数组本身是个对象。）

## 四、多个类型参数：`Pair<K, V>`

一个类型参数不够用时，可以写多个，用逗号隔开：

```java
public class Pair<K, V> {
    private final K key;
    private final V value;
    // ...
}
```

`K` 是 Key、`V` 是 Value 的惯例命名。用起来：

```java
Pair<String, Integer> age = new Pair<>("Albert", 30);
Pair<Integer, String> flipped = new Pair<>(1, "one");
```

```terminal
========== 4. 多个类型参数：Pair<K, V> ==========
Pair[Albert = 30]
Pair[1 = one]
key() 是 String：ALBERT
value() 是 Integer：31
static 工厂也能推类型：Pair[x = 1.5]
```

`Pair<String, Integer>` 和 `Pair<Integer, String>` 是**两个不同的类型**，
虽然来自同一个类。`age.key().toUpperCase()` 能编译，是因为编译器知道 `key()` 返回 `String`；
换成 `flipped.key().toUpperCase()` 就编译不过了——它的 `key()` 是 `Integer`。

### 4.1 `static` 方法用不了类上的类型参数

`Pair.of` 是个 `static` 方法，但它也用了 `K`、`V`。这不是类上那两个，而是它**自己声明**的：

```java
public static <K, V> Pair<K, V> of(K key, V value) {
    return new Pair<>(key, value);
}
```

为什么必须自己声明一份？因为**类上的类型参数属于对象**：
`Pair<String, Integer>` 的 `K` 是 String，`Pair<Integer, String>` 的 `K` 是 Integer，
同一个类里两个对象的 `K` 根本不是一回事。而 `static` 方法没有对象，那它该用哪个 `K`？

编译器不猜，直接报错：

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/generics/broken/StaticUsesClassTypeParam.java
src/main/java/dev/javalearning/generics/broken/StaticUsesClassTypeParam.java:24: error: non-static type variable T cannot be referenced from a static context
    public static T create() {   // ← static 方法里没有 T
                  ^
1 error
```

**`non-static type variable T cannot be referenced from a static context`**——
这句话在[类与对象](./04-类与对象.md)里见过类似的版本（`static` 方法里不能用实例字段），
这里是它在泛型上的翻版。**`static` 要用泛型，就自己声明一份。**

## 五、有界泛型：约束换来能力

现在 `Box<T>` 有个限制：`T` 被当成 `Object` 用，所以只能调 `Object` 的方法
（`toString()`、`equals()`……）。想调别的方法呢？

```java
public static <T> double half(T number) {
    return number.doubleValue() / 2;      // ← 编译不过
}
```

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/generics/broken/UnboundedCall.java
src/main/java/dev/javalearning/generics/broken/UnboundedCall.java:20: error: cannot find symbol
        return number.doubleValue() / 2;   // ← T 没约束，被当成 Object
                     ^
  symbol:   method doubleValue()
  location: variable number of type T
  where T is a type-variable:
    T extends Object declared in method <T>half(T)
1 error
```

**`cannot find symbol` / `location: variable number of type T` / `T extends Object`**——
javac 把话说得很清楚：`T` 被当成了 `Object`，而 `Object` 没有 `doubleValue()`。

那如果加一句"`T` 必须是 `Number` 的子类"呢？这就是**有界类型参数**（bounded type parameter）：

```java
public class NumberBox<T extends Number> {
    private final T content;

    public double doubleValue() {
        return content.doubleValue();      // ← 现在能调了
    }
}
```

```terminal
========== 5. 有界泛型：<T extends Number> ==========
intBox.doubleValue() = 10.0
doubleBox.get()      = 2.5
两个不同类型的盒子能相加：12.5
约束之后 T 当 Number 用，所以 doubleValue() 能调
代价：new NumberBox<String>("x") 编译不过，String 不在 Number 范围里
类和接口一起约束时，类必须写在前面：<T extends Number & Comparable<T>>
```

**约束换来了能力**：`T extends Number` 之后，编译器知道 `T` 一定是个 `Number`，
于是 `doubleValue()`、`intValue()` 这些方法就能调了。

代价在另一头：`new NumberBox<String>("x")` 编译不过了。

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/generics/broken/OutOfBounds.java
src/main/java/dev/javalearning/generics/broken/OutOfBounds.java:20: error: type argument String is not within bounds of type-variable T
        NumberBox<String> box = new NumberBox<>("不是数字");   // ← String 不在 Number 的范围内
                  ^
  where T is a type-variable:
    T extends Number declared in class NumberBox
src/main/java/dev/javalearning/generics/broken/OutOfBounds.java:20: error: cannot infer type arguments for NumberBox<>
        NumberBox<String> box = new NumberBox<>("不是数字");   // ← String 不在 Number 的范围内
                                ^
  reason: inference variable T has incompatible bounds
    upper bounds: Number
    lower bounds: String
  where T is a type-variable:
    T extends Number declared in class NumberBox
2 errors
```

**`type argument String is not within bounds of type-variable T`**——
`String` 不在 `Number` 的范围里。这正是我们要的：**该挡的挡在编译期。**

### 5.1 约束接口也写 `extends`，不写 `implements`

这是个特别容易记错的地方：

```java
public static <T extends Comparable<T>> T max(T a, T b) { ... }
```

`Comparable` 是**接口**，但约束它照样写 `extends`，**不能写 `implements`**。
尖括号里只有 `extends` 这一个关键字，不管后面跟的是类还是接口。

（记忆法：这里读作"T 是……的一种"，不是"T 实现了……"。）

### 5.2 类和接口一起约束时，类必须写在前面

一个类型参数可以有多个上界，用 `&` 连接：

```java
public static <T extends Number & Comparable<T>> T max(T a, T b) { ... }
```

这里的规则很硬：**类必须排第一，接口跟在后面。** 顺序写反就编译不过：

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/generics/broken/WrongBoundOrder.java
src/main/java/dev/javalearning/generics/broken/WrongBoundOrder.java:21: error: interface expected here
    public static <T extends Comparable<T> & Number> T max(T a, T b) {
                                             ^
1 error
```

**`interface expected here`**，指针正好停在 `Number` 上——因为编译器看到
`extends Comparable<T>` 之后，就把后面的位置当成了"还允许哪些接口"，
结果来了个 `Number` 这个类，它当然说"这里我要接口"。

> 这条规则的理由很实在：Java 的类只能继承一个，接口可以有很多。
> 所以"至多一个类 + 任意多个接口"正好用"第一个位置给类、后面全给接口"来表达。

本课的 `GenericsTest` 里就用了一个合法版本 `maxOf`：

```java
static <T extends Number & Comparable<T>> T maxOf(T a, T b) {
    return a.compareTo(b) >= 0 ? a : b;
}
```

`Integer` 既是 `Number` 也实现了 `Comparable<Integer>`，所以 `maxOf(3, 7)` 能跑。

## 六、泛型方法：`<T>` 写在返回类型之前

前面讲的都是泛型**类**。泛型还能只加在**方法**上：

```java
public static <T> void print(T content) {
    System.out.println(content);
}
```

注意 `<T>` 的位置——它在 `void` **之前**，也就是**返回类型之前**：

```
public static  <T>  void   print(T content)
              └┬─┘  └┬─┘
        类型参数声明  返回类型
```

第一次看很容易觉得别扭（`<T>` 夹在中间），但位置是死的：**类型参数声明永远在返回类型前面。**
有返回值时也一样：

```java
public static <T extends Number> double half(T number) {
    return number.doubleValue() / 2;
}
```

```terminal
========== 6. 泛型方法：<T> 写在返回类型之前 ==========
字符串也能打
42
3.14
一个方法搞定所有类型，方法自己声明了 <T>
Printer.half(10)   = 5.0
Printer.half(2.5)  = 1.25
half 的 T 有界，所以方法体里能调 doubleValue()
```

`Printer` 这个类本身**不是**泛型类（`class Printer`，没有尖括号），
但它的两个方法各自声明了 `T`。**类的泛型和方法的泛型是两套独立的东西**：

| | 泛型类 | 泛型方法 |
|---|---|---|
| 声明位置 | `class Box<T>` | `public static <T> void print(T t)` |
| 作用范围 | 整个类（字段、方法都能用） | 只有这个方法 |
| 谁决定 T | `new Box<String>` 时 | 调用方法时（通常自动推断） |
| `static` 能用吗 | 不能 | 能（它自己声明） |

调用时通常**不用写类型**，编译器从实参推：

```java
Printer.print("字符串也能打");    // 推断 T = String
Printer.print(42);                // 推断 T = Integer
Printer.half(10);                 // 推断 T = Integer
```

## 七、类型安全：错误该在编译期炸，还是在运行期炸

这一节是整课的核心。

回到那个"什么都能装"的诉求。不用泛型，最直觉的写法是 `List<Object>`：

```java
List<Object> loose = new ArrayList<>();
loose.add("Alice");
loose.add(42);              // 编译通过——因为 Object 什么都能装
```

两个 `add` 都编译通过，看起来很"灵活"。但取出来的时候麻烦来了：

```java
String wrong = (String) loose.get(1);    // 第 2 个明明是 Integer
```

```terminal
========== 7. 类型安全：List<Object> 的错要到运行期才炸 ==========
List<Object> 什么都能放，两个 add 都编译通过：[Alice, 42]
取出来是 Object，要用就得强转：
  ClassCastException: class java.lang.Integer cannot be cast to class java.lang.String
  ← 编译期一声不吭，运行到这一行才炸
List<String> 就不一样：strict.add(42) 编译不过，int 转不成 String
取出来直接是 String，强转都省了：ALICE
```

**`ClassCastException`——编译期一声不吭，运行到那一行才炸。**

这就是 `List<Object>` 的代价：它把"这里装的是什么"这个信息**扔掉了**。
扔掉的后果有两个，而且都很难受：

1. 取出来必须强转，代码里全是 `(String)`、`(Integer)`
2. **转错了编译器不知道**，要等到那一行真的被执行、真的转，才在运行期抛异常

第 2 点最要命。如果那行代码在某个很少走到的分支里，可能上线几个月才炸一次，
而且炸的时候离出错的地方（那个 `add(42)`）已经很远了，排查要翻很多代码。

换成 `List<String>` 呢？

```java
List<String> strict = new ArrayList<>();
strict.add("Alice");
strict.add(42);              // ← 编译不过
```

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/generics/broken/AddWrongType.java
src/main/java/dev/javalearning/generics/broken/AddWrongType.java:24: error: incompatible types: int cannot be converted to String
        names.add(42);   // ← List<String> 里塞不进 int
                  ^
Note: Some messages have been simplified; recompile with -Xdiags:verbose to get full output
1 error
```

**`incompatible types: int cannot be converted to String`**——
错误在**编译期**就被挡住了，`strict.add(42)` 这行代码根本进不了 class 文件。
而且取出来直接就是 `String`，强转也省了。

对比一下这两种写法：

| | `List<Object>` | `List<String>` |
|---|---|---|
| 往里放 | 什么都行 | 只有 String（编译期挡） |
| 取出来 | `Object`，要强转 | 直接是 `String` |
| 放错类型 | 编译通过，**运行期**炸 | **编译期**报错 |
| 错误离现场 | 很远（可能在另一段代码） | 就在这一行 |

> **泛型最核心的价值不是"少写代码"，而是把类型错误从运行期提前到编译期。**
> 编译期报错你当场就改了；运行期报错可能要等几个月，还可能是在生产环境。

这也解释了为什么第一节那两个 `Printer` 那么难受：它们不只是重复，
而是**编译器完全不知道它们是一回事**，什么检查都做不了。

## 八、类型擦除：泛型只活在编译期

现在到了一个很多人会惊讶的事实。看这段代码：

```java
List<String> strings = new ArrayList<>();
List<Integer> integers = new ArrayList<>();
System.out.println(strings.getClass() == integers.getClass());
```

猜猜打印什么？`false`？——**是 `true`。**

```terminal
========== 8. 类型擦除：泛型只活在编译期 ==========
strings.getClass() == integers.getClass() → true
new ArrayList<String>().getClass()  = java.util.ArrayList
new ArrayList<Integer>().getClass() = java.util.ArrayList
Box<String> 和 Box<Integer> 的 Class 也是同一个 → true
Box 里 content 字段运行期的类型        = class java.lang.Object
NumberBox 里 content 字段运行期的类型  = class java.lang.Number
← 擦成上界：没约束擦成 Object，约束了擦成 Number
```

两个 `getClass()` 是**同一个 Class 对象**。`List<String>` 和 `List<Integer>`
在运行期根本没有区别——它们都是 `java.util.ArrayList`。

这个现象叫**类型擦除**（type erasure）：

> 泛型的类型信息**只存在于编译期**。编译器用它检查代码，检查完就把它擦掉，
> 生成的字面量里只剩裸类型。运行期 JVM 看到的 `Box` 就是 `Box`，
> 它不知道你写的是 `Box<String>` 还是 `Box<Integer>`。

擦成什么？看最后两行——**擦成上界**：

| 声明 | 擦除后 |
|---|---|
| `class Box<T>` | `T` → `Object` |
| `class NumberBox<T extends Number>` | `T` → `Number` |
| `List<? extends Number>` 里的元素 | `Number` |

上面那两行是**用反射直接读字段类型**读出来的，不是我推的：

```java
Box.class.getDeclaredField("content").getType()          // class java.lang.Object
NumberBox.class.getDeclaredField("content").getType()    // class java.lang.Number
```

`Box` 的 `content` 字段在字节码里就是 `Object` 类型，`NumberBox` 的就是 `Number`。
**泛型参数在运行期不存在，这是字节码级别的事实。**

### 8.1 擦除带来的三个后果

**① 泛型实参在运行期检查不了。** 面对一个 `Object`，`o instanceof List<String>`
编译不过——因为运行期没有 `List<String>` 这个东西，只有 `List`：

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/generics/broken/InstanceofErased.java
src/main/java/dev/javalearning/generics/broken/InstanceofErased.java:28: error: Object cannot be safely cast to List<String>
        System.out.println(o instanceof List<String>);   // ← 擦除后检查不了
                           ^
1 error
```

**`Object cannot be safely cast to List<String>`**。

这里有个坑要说清楚，我一开始也想错了：**并不是所有
`instanceof List<String>` 都编译不过。** 如果变量的静态类型已经是
`List<String>`，那 `list instanceof List<String>` 反而合法：

```java
List<String> list = new ArrayList<>();
list instanceof List<String>    // ← 能编译
```

因为编译器**已经从声明里知道了**类型实参，这个检查恒为 `true`、没有任何意义，
它没必要拦。真正的规则不是"泛型不能用于 `instanceof`"，而是
**"编译器必须能证明这个转型是安全的"**：

| 写法 | 结果 | 为什么 |
|---|---|---|
| `List<String> l; l instanceof List<String>` | 能编译 | 声明里已经知道，恒真 |
| `Object o; o instanceof List<String>` | **编译不过** | 擦除后编译器证明不了 |
| `List<String> l; l instanceof List<Integer>` | **编译不过** | 两者不可能相容 |

而 `o instanceof List<?>` 是合法的——`?` 不检查实参，运行期做得出来：

```java
Object o = new ArrayList<String>();
o instanceof List<?>     // ← 能编译，结果是 true
```


**② 泛型数组创建不了。** `new T[10]` 编译不过：

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/generics/broken/GenericArrayCreation.java
src/main/java/dev/javalearning/generics/broken/GenericArrayCreation.java:19: error: generic array creation
        return new T[10];   // ← 泛型数组创建不了
               ^
1 error
```

**`generic array creation`**。理由：数组在运行期是知道自己元素类型的
（往 `String[]` 里塞 `Integer` 会抛 `ArrayStoreException`），
可 `T` 在运行期已经没了，JVM 不知道该检查什么类型，所以干脆禁止。

**③ 为什么 `Box<int>` 不行**（第三节那个问题）。`T` 要擦成 `Object`，
而 `Object` 装不了基本类型。擦除是那个限制的根源。

### 8.2 擦除是历史包袱，也是兼容性的代价

你可能会问：为什么要擦除，不保留泛型信息？

因为 Java 5 引入泛型时，**必须让新代码和老代码能互相调用**。
如果 `List<String>` 和 `List` 在运行期是不同的类，那所有泛型出现之前写的库
（字节码里全是裸 `List`）就全部不能用了。擦除让
`List<String>` 在运行期**就是** `List`，老库不用改一行。

代价就是上面那三条限制。这是 Java 泛型和 C# 泛型最大的区别之一
（C# 保留运行期泛型信息，所以能 `new T[]`、能做 `typeof(List<string>)`）。

## 九、通配符：`? extends` 与 `? super`

回到一个具体问题。写一个"求所有数字之和"的方法：

```java
public static double sum(List<Number> numbers) { ... }
```

`List<Number>` 收 `List<Number>`，没问题。但 `List<Integer>` 呢？

**传不进去。** 这是本课最反直觉的一点：

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/generics/broken/StringListIsNotObjectList.java
src/main/java/dev/javalearning/generics/broken/StringListIsNotObjectList.java:25: error: incompatible types: List<String> cannot be converted to List<Object>
        List<Object> objects = names;   // ← 编译不过：泛型不协变
                               ^
1 error
```

**`incompatible types: List<String> cannot be converted to List<Object>`**。
上面这个例子是 `String`/`Object`，换成 `Integer`/`Number` 一模一样：
**`List<Integer>` 不是 `List<Number>` 的子类型。**

### 9.1 为什么 `List<String>` 不是 `List<Object>`

很多人绕不过来：`String` 明明是 `Object` 的子类，凭什么 `List<String>` 不是
`List<Object>` 的子类？

因为**如果允许，类型安全就崩了**。假设编译器放行：

```java
List<String> names = new ArrayList<>();
names.add("Alice");

List<Object> objects = names;   // 假设这行合法
objects.add(42);                // List<Object> 当然能放 Integer
                                // 但它实际是那个 names！
String first = names.get(0);    // 拿到的可能是个 Integer → 运行期炸
```

矛盾的关键在 `objects.add(42)`：**"能往里写"和"能往外读"是一对约束。**
`List<Object>` 承诺"什么都能写进去"，而 `names` 承诺"读出来一定是 String"。
两个承诺不能同时成立，所以编译器干脆禁止这种赋值。

> 术语：`List<String>` 和 `List<Object>` 之间**没有子类型关系**，
> 这叫泛型的**不变性**（invariance）。数组是"协变"的（`String[]` 是 `Object[]` 的子类型），
> 所以数组允许上面的操作，代价是运行期的 `ArrayStoreException`。
> **泛型选择了不变性，把错误挪到了编译期**——这正是本课反复在讲的那件事。

### 9.2 `?` 是"未知的某一种类型"

既然 `List<Integer>` 传不进 `List<Number>`，那 `sum` 怎么写才能两种都收？

用**通配符**（wildcard）`?`。`List<? extends Number>` 的意思是
"元素类型是 Number 的**某个**子类的 List"——不指定是哪个：

```java
public static double sum(List<? extends Number> numbers) {
    double total = 0;
    for (Number number : numbers) {
        total += number.doubleValue();     // 能读，读出来当 Number 用
    }
    return total;
}
```

```terminal
========== 9. 通配符：? / ? extends / ? super ==========
sum(List<Integer>) = 6.0
sum(List<Double>)  = 4.0
sum 的参数是 List<? extends Number>，两种都能收
addAll 往 List<Number> 里加 → [1, 2, 3]
addAll 往 List<Object> 里加 → [7]
addAll 的参数是 List<? super Integer>，Number 和 Object 都能收
但 List<String> 不是 List<Object>：直接赋值编译不过
```

`List<Integer>` 和 `List<Double>` 现在都能传进来了。但**有得必有失**——
`? extends Number` 的列表**不能往里写**：

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/generics/broken/ProducerCannotAdd.java
src/main/java/dev/javalearning/generics/broken/ProducerCannotAdd.java:22: error: incompatible types: int cannot be converted to CAP#1
        producer.add(42);   // ← ? extends Number 不让写
                     ^
  where CAP#1 is a fresh type-variable:
    CAP#1 extends Number from capture of ? extends Number
Note: Some messages have been simplified; recompile with -Xdiags:verbose to get full output
1 error
```

**`incompatible types: int cannot be converted to CAP#1`**，
后面还跟了一句 `CAP#1 extends Number from capture of ? extends Number`。

`CAP#1` 是编译器给这个通配符起的一个临时名字（capture，捕获）。
它的意思是：**"我不知道 `?` 到底是 Integer 还是 Double，所以我不敢让你往里写。"**
万一这个 `List` 实际是 `List<Double>`，往里塞 `Integer` 就出事了。
（注意第 10 节输出里 `producer.add(42)` 编译不过、而 `consumer.add(42)` 可以，
原因就在这儿。）

于是三种通配符的能力边界很清楚了：

| 写法 | 能读吗 | 能写吗 | 读出来是什么 |
|---|---|---|---|
| `List<?>` | 能 | **不能** | `Object` |
| `List<? extends Number>` | 能 | **不能** | `Number` |
| `List<? super Integer>` | 能（只能当 `Object`） | 能 | `Object` |

### 9.3 `? super` 是反过来的约束

有"生产者"就有"消费者"。往集合里**写**东西的方法，用下界 `? super`：

```java
public static void addAll(List<? super Integer> target, Integer... values) {
    for (Integer value : values) {
        target.add(value);      // 能写
    }
}
```

`List<? super Integer>` 的意思是"元素类型是 Integer 的**某个父类**的 List"。
`Integer` 的父类有 `Number`、`Object`，所以这三种实参都能收：
`List<Integer>`、`List<Number>`、`List<Object>`——往里面塞 `Integer` 对它们都安全。

代价在另一头：**读出来的东西只能是 `Object`**，因为编译器不知道那个"父类"到底是谁，
只能保证它至少是 `Object`。这就是第 10 节输出里那句"信息已经丢了"。

## 十、PECS：什么时候用 `extends`，什么时候用 `super`

`? extends` 和 `? super` 该选哪个？一句话：

> **PECS — Producer Extends, Consumer Super**
> （生产者用 extends，消费者用 super）

- **生产者**（Producer）：这个集合**给你提供**数据，你只从它里面**读** → 用 `? extends T`
- **消费者**（Consumer）：这个集合**接收**你的数据，你只往它里面**写** → 用 `? super T`

```terminal
========== 10. PECS：Producer Extends, Consumer Super ==========
只读的用 extends：producer.get(0) = 1
  producer.add(42) 编译不过：? extends Number 不知道具体是哪个子类
只写的用 super：consumer.add(42) 之后 = [42]
  consumer.get(0) 拿到的是 Object，信息已经丢了
要读又要写，就别用通配符，老老实实写 List<Integer>
```

记法：**`extends` 是"至少能当 T 用"（读得出来），`super` 是"至少能装 T"（写得进去）。**
两个方向正好相反，所以一个通配符不可能既方便读又方便写——
**要读又要写，就别用通配符**，老老实实写具体的 `List<Integer>`。

JDK 里到处都是 PECS。比如 `Collections.copy`：

```java
public static <T> void copy(List<? super T> dest, List<? extends T> src)
//                          └── 消费者：往里写      └── 生产者：从里读
```

`src` 只被读（`extends`），`dest` 只被写（`super`）——教科书级的一行。

**这一节可以只记结论**：写 API 时，参数里出现泛型集合，先问自己
"我是从它读，还是往它写"，答案直接决定用 `extends` 还是 `super`。

## 十一、不推荐的用法

### ① 用 `List<Object>` 代替泛型

```java
List<Object> list = new ArrayList<>();      // ← 等于放弃类型检查
```

它把编译期检查换成了运行期强转，正是第七节那个 `ClassCastException` 的来源。
**唯一的例外**是 `List<Object>` 作为 `? super` 的上界（比如 `List<? super Integer>`
可以接一个 `List<Object>`）——那是把 `Object` 当"能装下一切的容器"用，是合理的。

### ② 用原始类型（raw type）

```java
List list = new ArrayList();      // ← 没有类型参数
```

这是 Java 5 之前的写法，为了兼容老代码还留着。编译器**只给警告，不给错误**：

```terminal

```

打开 `-Xlint` 才会说详细一点：

`[rawtypes]` 和 `[unchecked]`——**警告不是错误，程序照跑**。这就是它危险的地方：
第七节那个 `ClassCastException`，用 raw type 一样躲不掉，而且更容易发生：

```terminal

```

对比一下就很清楚：`List<String>` 的 `add(42)` 是**编译错误**，
raw type 的 `add(42)` 只是**警告**，然后错误留到运行期。
**新代码永远不要写 raw type。**（唯一必须用它的地方是和泛型出现之前的
老 API 打交道，而且应该在最小范围内用，并加 `@SuppressWarnings` 说明理由。）

### ③ 用泛型数组

```java
T[] array = new T[10];                    // ← generic array creation
```

第八节讲过原因：运行期 `T` 不存在，JVM 不知道该检查什么。
要"泛型 + 数组"，用 `List<T>` 代替数组，或者传一个 `Class<T>` 进来
用 `Array.newInstance` 造——但那已经是反射的范畴了。

### ④ 让 `static` 方法引用类上的类型参数

```java
public class Box<T> {
    public static T create() { ... }     // ← 编译不过
}
```

`static` 方法没有对象，而类上的 `T` 属于对象。要么给方法自己声明一份
（`public static <T> T create()`），要么把类改成泛型方法所在的工具类。
第四节讲过这个错误。

### ⑤ 别为了"少写一个类"硬上泛型

泛型不是免费的：类型参数一多，签名会变得很长
（`<T extends Comparable<? super T>>` 这种），读起来很费劲。
**一个类只被一两种类型用、而且逻辑很短时，写死类型反而更清楚。**
泛型的正当理由是"同一个逻辑要服务多种类型"，不是"想少写几行"。

## 十二、这一课的术语表

- **泛型**（generics）—— 把类型本身参数化，让一份代码服务多种类型
- **类型参数**（type parameter）—— `Box<T>` 里的 `T`，一个占位的类型名字
- **类型实参**（type argument）—— `Box<String>` 里的 `String`，实际填进去的类型
- **泛型类**（generic class）—— `class Box<T>`，类型参数作用于整个类
- **泛型方法**（generic method）—— `public static <T> void print(T t)`，`<T>` 写在返回类型之前
- **钻石运算符**（diamond operator）—— `new Box<>("x")`，让编译器从上下文推断类型实参
- **装箱类型**（wrapper type）—— `Integer`、`Double` 等；类型参数不能用基本类型，只能用它们
- **有界类型参数**（bounded type parameter）—— `<T extends Number>`，约束换来调用 T 身上方法的能力
- **上界**（upper bound）—— `extends` 后面那个类型；约束接口也写 `extends`
- **多个上界**（multiple bounds）—— `<T extends Number & Comparable<T>>`，**类必须写在最前面**
- **类型安全**（type safety）—— 让类型错误在编译期暴露，而不是运行期
- **类型擦除**（type erasure）—— 泛型信息只存在于编译期，运行期被擦成 `Object` 或上界
- **通配符**（wildcard）—— `?`，表示"未知的某一种类型"
- **上界通配符**（upper-bounded wildcard）—— `? extends T`，能读不能写
- **下界通配符**（lower-bounded wildcard）—— `? super T`，能写但读出来是 `Object`
- **不变性**（invariance）—— `List<String>` 不是 `List<Object>` 的子类型
- **捕获**（capture）—— 编译器给 `?` 起的临时名字，错误信息里的 `CAP#1`
- **PECS**—— Producer Extends, Consumer Super；只读用 `extends`，只写用 `super`
- **原始类型**（raw type）—— 不写类型参数的 `List`，只给警告，等于放弃编译期检查

## 十三、下一课

这一课把类型从"写死的"变成了"参数化的"，但还有个东西一直很碍事：**行为**。

看第七节那段代码：

```java
List<String> strict = new ArrayList<>();
strict.add("Alice");
// 想按某种规则筛选、排序、打印呢？
```

要给一个方法传"一段逻辑"，得先为它建一个类、实现一个接口、再 `new` 一个对象出来——
哪怕那段逻辑只有一行。这就是**匿名内部类**的由来，也是它的痛苦。

下一课[Lambda 表达式](./07-Lambda表达式.md) 要讲的就是：**怎么把"一段逻辑"像值一样传来传去。**
一个接口、一个箭头、一行代码，把上面那三行样板全干掉。

顺带说一句，本课的通配符看着绕，但它是后面所有集合 API 的基础——
`Stream` 的 `map`、`filter`，`Optional` 的 `map`，签名里全是泛型。
**泛型看懂了，那些签名才读得下去。**
