## 一个最小的方法长什么样

```java
// src: src/main/java/dev/javaquest/basics/methods/MethodsDemo.java
public static int add(int a, int b) {
    return a + b;
}
```

四部分：

| 部分 | 说明 |
|---|---|
| `public` | 可见性。`private` < 默认 < `protected` < `public` |
| `static` | 属于类还是属于对象。第 4 章会详细讲 |
| `int` | 返回类型。`void` 表示不返回值 |
| `add(int a, int b)` | 方法名 + 参数列表 |

Java 里**方法名和参数列表合起来才构成方法签名**，所以下面两个能共存：

`MethodsTest.Overloading#overloadsArePickedByTheArgumentList`

```java
describe(42)         // int
describe(42, "岁")    // int, String
describe(1, 2, 3)    // int, int, int
```

这叫**重载**（overloading）：同名、不同参数、同一个方法。
调用时编译器按你传的参数挑一个，所以重载必须在编译期就定下来。

对比一下**重写**（overriding，第 5 章讲）：子类重新定义父类的方法，
运行期才决定调哪个。「重载编译期定，重写运行期定」这句话要记牢。

## 参数传递：只有值传递，没有引用传递

Java 的方法参数**一律是值传递**。这句话几乎所有人第一次听都不同意，
所以下面两组对照值得都跑一遍。

### 基本类型：完全隔离

`MethodsTest.Parameters#primitivesArePassedByValue`

```java
int x = 1;
reassignParameter(x);   // 方法内部：x = 100

x                       // 还是 1
```

传进去的是 `1` 这个值的副本。方法里的 `x` 和外面的 `x` 是两个不同的变量。

### 对象：传的是「地址的副本」，指向同一个对象

`MethodsTest.Parameters#objectsShareTheSameTarget`

```java
int[] data = {1, 2, 3};
mutateSharedObject(data);   // 方法内部：data[0] = 100

data                     // [100, 2, 3] 变了！
```

把一个变量想象成一张**写着地址的纸条**，把纸条复印一份传给方法：

- 方法改纸条上的地址 → 只影响复印件 → 调用方看不到
- 方法按地址找到对象、改对象的内容 → 两个变量都指向那个对象 → 调用方看得见

这就解释清了「为什么说是值传递却又看得见改动」。

### 在方法里把参数重新指向别处

`MethodsTest.Parameters#reassigningTheParameterDoesNotLeakOut`

```java
int[] data = {1, 2, 3};
reassignParameterToNewArray(data);   // 方法内部：data = new int[]{100}

data                     // 还是 [1, 2, 3]
```

方法里换了一张新纸条，上面的新地址指向一个只存在于方法栈上的对象。
方法一返回，那个对象就没了，调用方的纸条原封不动。

**这三条合起来是最容易被面试问到的一组题。**
`MethodExercisesTest#exerciseReassigningParameterDoesNotLeak` 练第 3 条，
`MethodExercisesTest#exerciseMutatingArrayContentsIsVisible` 练第 2 条。

### 传可变对象 = 交出控制权

`MethodsTest.Parameters#passingAMutableObjectHandsOverControl`

```java
Field box = new Field(1);
int before = changeAndReport(box);   // 返回改动前的值，同时把 box.value 改成 100

box.value      // 100，调用方的数据被改了
```

方法默认可以随便改你传进去的对象。想避免这种「意外副作用」有三种做法：

```java
// 1. 传不可变对象（String、record、Integer）—— 最省心，首选
// 2. 想改就复制一份再改
List<String> copy = new ArrayList<>(original);
// 3. 明确方法契约：方法名说明它会不会改
//    比如 parseInt() 纯读取，sortInPlace() 明确会改
```

第 8 章的 `List.copyOf()`、`Collections.unmodifiableList()` 也是这类思路。

## 返回值

`MethodsTest.ReturnValues#returningMethodsGiveYouTheValue`

```java
int sum = add(2, 3);    // 5
```

一个方法**要么返回值要么不返回**，不能「有时返回有时不返回」。
所以想「可能有个结果」时，返回值类型得能表示「没有」——用 `Optional`（第 11 章）。

### void 方法里的 return 是「走人」不是「返回值」

`MethodsTest.ReturnValues#voidReturnOnlyExitsEarly`

```java
void printAndReturnEarly(int limit) {
    for (int i = 0; i < limit; i++) {
        if (i == 2) {
            return;         // 不是「返回 2」，是「别返回了，直接走人」
        }
        System.out.println("i = " + i);
    }
    System.out.println("循环正常走完");
}

printAndReturnEarly(5);
// 输出 i = 0 / i = 1，然后走人，不打印「循环正常走完」
// （limit 必须大于 2，否则循环正常跑完，走不到 return 那一步）
```

`return` 在 `void` 方法里唯一的作用是**提前结束**。
它很适合处理「遇到特殊情况就退出」的流程，嵌套会少很多。

反例：

```java
void f() {
    return 5;      // 编译报错：void 方法不能返回值
}
int  g() {
    // 没有 return   // 编译报错：可能不返回值
}
```

## 局部变量的作用域

`MethodsTest.Scope#localScopeEndsAtTheClosingBrace`

```java
public static int f() {
    int result;
    if (true) {
        int inner = 10;
        result = inner;      // OK，inner 在这个块里可见
    }
    // int inner = 20;       // 编译报错：inner 的作用域到上面那个 } 就结束了
    return result;
}
```

规则：变量从声明处开始，到**包含它的那对花括号结束**为止。
`{}` 不只是给人看的排版，它是编译器的可见性边界。

这也是为什么 `if (条件) { ... }` 明明可以省掉大括号却强烈建议加上：

```java
// 能编译，但下一个 if 会被无条件执行——经典 bug
if (ok)
    doSomething();
if (ok)
    doSomethingElse();     // 这里已经没有 if 了！
```

## 可变参数 `int...`

`MethodsTest.Varargs#varargsIsJustAnArray`、`MethodsTest.Varargs#passingAnArrayIsIdenticalToPassingScalars`

```java
int sumOfAll(int... numbers) { ... }

sumOfAll(1, 2, 3)      // 6
sumOfAll()             // 0，空数组
sumOfAll(new int[]{1, 2, 3})   // 6，完全等价
```

本质就是 `int[]`，编译器在调用点自动帮你打包成数组。
所以方法体里可以正常 `for (int n : numbers)`，
也可以把它整个传给另一个可变参数方法。

`MethodExercisesTest#exerciseVarargsIsAnArrayInside` 是练这个。

规则：

1. 可变参数必须是**最后一个**参数
2. 一个方法**只能有一个**可变参数
3. 可变参数和重载容易冲突。`f(int a)` 和 `f(int... a)` 能共存吗？

```java
void f(int a) { }
void f(int... a) { }

f(1);        // 编译报错：歧义，编译器不知道该调哪个
```

所以别写这种重载。要么改成不同名，要么让参数个数真的区分开。

## 本章要点

- Java 只有值传递。传对象传的是「地址的副本」，所以改内容看得见、改指向看不见
- 重载靠参数列表区分，编译期定；重写是运行期定
- `void` 方法的 `return` 只表示提前结束
- 局部变量作用域到所属花括号结束
- `int...` 就是 `int[]`，可变参数只能放最后且只能有一个
