# 03 · 方法

先看一个最小的 Java 方法：

```java
// src: src/main/java/dev/javaquest/basics/methods/MethodsDemo.java
public static int add(int a, int b) {
    return a + b;
}
```

四部分：

| 部分 | 说明 |
|---|---|
| `public` | 可见性。`private` < 默认（包内） < `protected` < `public` |
| `static` | 属于类还是属于对象，第 4 章详细讲 |
| `int` | 返回类型。`void` 表示不返回值 |
| `add(int a, int b)` | 方法名 + 参数列表 |

方法可以理解成一个**有名字、有边界的转换**：进去一些值，出来一个结果，
或者什么都不出来。这条边界有三个面，也是这一章的地图：

| 面 | 问题 | 关键概念 |
|---|---|---|
| **输入** | 参数进来时发生了什么？ | 参数是「值的副本」 |
| **输出** | 结果怎么出去？ | `return` 给值，或 `void` 不给 |
| **内部** | 方法里声明的东西活多久？ | 局部作用域 |

大部分关于方法的疑问，都能归到这张表里。

# 一、同名的方法可以有多个版本

Java 里**方法名和参数列表合起来才构成方法标识**，所以同名方法可以共存：

```java
describe(42)         // 版本 A：int
describe(42, "岁")    // 版本 B：int, String
describe(1, 2, 3)    // 版本 C：int, int, int
```

这叫**重载**（overloading）。调用时编译器按你实际传的参数挑一个版本，
所以重载必须在编译期就定下来。

对照一下**重写**（overriding，第 5 章讲）：子类重新定义父类的方法，
运行期才决定调哪个。一句话记：**重载编译期定，重写运行期定**。

对应测试：同名方法可以有多个版本，靠参数个数或类型区分。

# 二、输入：参数进来时发生了什么

## 为什么传进去之后，调用方的变量没变？

Java 的方法参数**一律是值传递**。也就是说，调用时发生的是：
把参数的值复制一份，交给方法里的形参。

```java
int x = 1;
reassignParameter(x);   // 方法内部：x = 100

x                       // 还是 1
```

方法里的 `x` 和外面的 `x` 是两个不同的变量，改一个不影响另一个。

## 那为什么改数组内容，调用方就看得见？

因为数组是引用类型，变量里装的是地址：

```java
int[] data = {1, 2, 3};
mutateSharedObject(data);   // 方法内部：data[0] = 100

data                     // [100, 2, 3]，调用方看得见
```

把「传对象」这件事拆开看就清楚了。想象每个变量都是一张**写着地址的纸条**：

```
调用方的 data  →  [纸条: 地址A]
方法的   data  →  [纸条: 地址A]     ← 同一张纸条的复印件
                            ↓
                    地址A 指向的对象
```

于是有两种操作，结果完全不同：

| 方法里做的事 | 改的是 | 调用方 |
|---|---|---|
| `data = new int[]{100}` | 复印件上的地址 | 看不到 |
| `data[0] = 100` | 地址指向的那个对象 | 看得到 |

「只有值传递」和「改内容看得见」这两件事因此不矛盾：
值传递说的是**纸条被复印了**，而两个复印件指向的是**同一个对象**。

## 为什么在方法里把参数重新指向别处，调用方看不到？

```java
int[] data = {1, 2, 3};
reassignParameterToNewArray(data);   // 方法内部：data = new int[]{100}

data                     // 还是 [1, 2, 3]
```

方法里换了一张新纸条，上面写着新地址。那个新对象只存在于方法的栈上，
方法一返回就被回收了——调用方手里那张纸条还指着老地址，自然什么都没变。

想验证这三条，最直接的办法是去跑：
「基本类型是值传递」「对象是值传递地址」这两条会告诉你「改内容」和「改值」的分界，
「在方法内把参数重新指向别处」则告诉你另一半。

这一节对应练习 1 和练习 2：
在方法里把数组参数重新指向新数组，调用方看得见吗？改数组第一个元素呢？

## 传可变对象，等于把控制权交出去

上面第三种情形（改对象内容）是 Java 里最常见的副作用来源：

```java
Field box = new Field(1);
int before = changeAndReport(box);   // 返回改动前的值，同时把 box.value 改成 100

box.value      // 100，调用方的数据被改了
```

方法默认可以修改你传进去的对象。想控制这一点有三种做法：

```java
// 1. 传不可变对象（String、Integer、record）—— 最省心，首选
// 2. 想改就先复制一份再改
List<String> copy = new ArrayList<>(original);
// 3. 用方法名说清契约：parseInt() 纯读取，sortInPlace() 明确会改
```

第 8 章的 `List.copyOf()`、`Collections.unmodifiableList()` 属于第 2 种思路。

对应测试：传可变对象等于交出控制权，方法能改你的数据。

## `int...` 到底是什么？

可变参数**本质就是一个数组**，编译器在调用点帮你把散着的参数打包：

```java
int sumOfAll(int... numbers) { ... }

sumOfAll(1, 2, 3)               // 6
sumOfAll()                      // 0，空数组
sumOfAll(new int[]{1, 2, 3})    // 6，和传散数完全等价
```

所以方法体里可以正常 `for (int n : numbers)`，也可以把它整个转发给
另一个可变参数方法。

两条规则：

1. 可变参数必须是**最后一个**参数
2. 一个方法**只能有一个**可变参数

还有一条要注意的：可变参数和重载容易冲突。

```java
void f(int a) { }
void f(int... a) { }

f(1);        // 两个版本都匹配得上，编译器不知道该调哪个
```

两个方法能共存，但 `f(1)` 两个都匹配得上。遇到这种情况，
换个方法名或者让参数个数真正区分开，比留着歧义清楚。

去跑「int... 就是 int[]」和「传数组和传散数完全等价」这两条，
第二条专门用来消掉「这俩写法真的没区别吗」的疑问。

这一节对应练习 3：可变参数在方法内部是什么类型？

# 三、输出：结果怎么出去

## return 给值

```java
int sum = add(2, 3);    // 5
```

**返回类型在声明时就固定了**：一个方法不能有时返回 `int`、有时返回 `void`。
所以当你想表达「可能有个结果」时，返回类型本身得能表示「没有」——
Java 的做法是 `Optional`（第 11 章会讲）。

这和「代码里写了几处 `return`」是两回事。下面这样完全合法：

```java
int sign(int x) {
    if (x < 0) return -1;     // 两处 return，返回的都是 int
    if (x > 0) return 1;
    return 0;                  // 所有路径都有返回值
}
```

编译器检查的是「每条路径是否都返回了声明的类型」，不是「return 出现了几次」。

## 为什么 `void` 方法里的 `return` 不能带值？

因为 `void` 的意思就是「这个方法不产生结果」。此时 `return` 的作用不是返回值，
而是**结束方法**，也就是提前退出：

```java
void printAndReturnEarly(int limit) {
    for (int i = 0; i < limit; i++) {
        if (i == 2) {
            return;         // 不是「返回 2」，是「别管结果了，直接走人」
        }
        System.out.println("i = " + i);
    }
    System.out.println("循环正常走完");
}

printAndReturnEarly(5);
// 输出 i = 0 / i = 1，然后走人，不打印「循环正常走完」
// （limit 得大于 2，否则循环正常跑完，走不到 return 那一步）
```

这个写法在处理「遇到特殊情况就退出」时很顺手，能省掉不少嵌套：

```java
// 嵌套 if
if (data != null) {
    if (!data.isEmpty()) {
        process(data);
    }
}

// 提前 return，扁平一层
if (data == null) return;
if (data.isEmpty()) return;
process(data);
```

编译器也会在这两处拦住你：

```java
void f() {
    return 5;      // void 方法不产生结果，带值编译器不让过
}

int g() {
    // 没有 return   // 这条路径没有返回值，编译器不让过
}
```

两条对照着跑：「有返回值的方法，return 直接给出结果」和
「void 方法里的 return 只是提前结束」，差别就在返回值这一处。

# 四、内部：方法里声明的东西活多久

## 局部变量的作用域到花括号结束

```java
public static int f() {
    int result;
    if (true) {
        int inner = 10;
        result = inner;      // OK，inner 在这个块里可见
    }
    // int inner = 20;       // 作用域到上面那个 } 就结束了，看不见 inner
    return result;
}
```

规则是：变量从声明处开始，到**包含它的那对花括号结束**为止。
`{}` 不只是排版，它是编译器的可见性边界——出了边界，变量就没了。

### 那为什么方法里声明的变量不会泄漏到外面？

因为方法体本身就是一对花括号。方法结束时，这一层边界也同时结束，
里面的局部变量跟着一起消失。

```java
int makeCounter() {
    int count = 0;      // count 从头到尾只在方法内部可见
    return count + 1;
}

// count = 5;            // count 的作用域到方法结束就没了，这里看不见
```

这一点在设计上是必要的：每个方法都有一套干净的局部命名空间，
两个方法里都叫 `i` 或 `tmp` 不会互相干扰，方法内部也不用担心
「这个名字和外面重名了怎么办」。

（至于 `if` 后面要不要加大括号，那是 `if` 自己的作用域问题，
属于上一章的内容，这里不展开。）

对应测试：局部变量的作用域到所属花括号结束为止。

## 本章要点

回到那张表——方法的边界有三个面。如果只记得四件事：

- **参数一律是值的传递。** 传对象时传的是地址的副本，所以「改对象内容」
  调用方看得见，「改指向」看不见
- **返回类型在声明时就固定了。** `void` 方法的 `return` 表示提前结束，不带值；
  「可能没有结果」用 `Optional`
- `int...` 就是 `int[]`，只能放最后且只能有一个；
  重载靠参数列表区分（编译期定），重写是运行期定
- 局部变量作用域到所属花括号结束，方法结束时一并消失——
  所以两个方法里都叫 `i` 不会打架
