上一课我们讲清了变量里装的是什么。这一课讲**怎么把一段逻辑收进一个盒子里，
然后看这个盒子和外面怎么交换数据**。

就是方法（method）。

方法每门语言都有，看起来没什么可讲的。但 Java 有一条特别容易栽进去的规矩，
而且它栽人的方式很阴：**平时完全正常，某天突然对不上账**。我们先来看它。

---

## 一、先让代码疼一次：为什么改了参数，外面没反应？

新手几乎都写过这样的代码，而且几乎都困惑过：

```java
public class Demo {
    public static void main(String[] args) {
        int x = 10;
        change(x);
        System.out.println(x);   // 心里以为是 999，实际打印 10
    }

    static void change(int x) {
        x = 999;
    }
}
```

`change` 里明明把 `x` 改成 999 了，为什么外面还是 10？是不是 `x` 写错了？是不是方法没被调用？

都不是。我们把这个实验做完整——不光改基本类型，还试试数组。这就是
[`MethodsDemo.java`](../src/main/java/dev/javalearning/basics/methods/MethodsDemo.java) 的前三节：

```terminal
$ java src/main/java/dev/javalearning/basics/methods/MethodsDemo.java

========== 1. 值传递：方法里改了参数，外面毫无变化 ==========
改之前 x = 10
改之后 x = 10   ← 一点没动

========== 2. 同一个对象：数组就能改到，因为拿到的是同一份数据的钥匙 ==========
改之前 array = [1, 2, 3]
改之后 array = [99, 2, 3]   ← 真的改了

========== 3. 但把参数重新指向别处，外面还是看不见 ==========
改之前 array2 = [1, 2, 3]
改之后 array2 = [1, 2, 3]   ← 没变

========== 4. 重载：同名不同参，编译器按参数列表挑 ==========
overload(1)      → 一个 int：1
overload(1, 2)   → 两个 int：1,2
overload("ab")   → 一个 String：ab

========== 5. 可变参数：个数不定，本质上是个数组 ==========
sum()           → 0
sum(1)          → 1
sum(1, 2, 3)    → 6
sum(already)    → 9   ← 数组可以直接传
pick(1) 选中了   → 单个 Integer（不是可变参数那个）

========== 6. return 在 String 方法里：提前溜走，不带值 ==========
grade(91) → 优秀
grade(75) → 及格
grade(-1) → 成绩不合法

========== 7. 传可变对象 = 交出控制权 ==========
方法把列表 clear 之后，调用方看到的 size = 0   ← 被掏空了

========== 8. 局部变量的作用域到花括号结束 ==========
内层花括号里 inner = 1
for 里声明的 i = 0
（离开花括号，inner 和 i 都不存在了）
```

后面五节还会反复引用这里的输出，所以先给全貌。我们一节一节来看。

三行输出，三种命运，全部**真跑出来的**。这里头的门道就是这一课的主线：

- 基本类型：改了白改
- 数组**内容**：改得动
- 把参数**重新指向**别处：改了白改

同一个方法调用，差别为什么这么大？要回答这个问题，得回到上一课的结论——
**变量里装的是值，还是地址。**

## 二、正解：Java 只有值传递，但「值」有两种

这句话是 Java 里最著名也最容易被讲糊的一句：

> **Java 是纯粹的值传递（pass by value）。**

但"值"有两种，所以看起来像是有时候传值、有时候传地址。

### 2.1 基本类型：传的是那份值本身

调用方法时，`x` 里装的那个 `10` 被**复制**了一份，交给形参。方法里改的是那份拷贝，
调用方那个变量压根不参与：

```java
static void change(int x) {
    x = 999;   // 改的是形参那份拷贝
}
```

形参和实参是两个不同的盒子，各装一个 `10`。改形参，实参当然没感觉。

### 2.2 对象（包括数组）：传的是那份地址

`int[] array = {1, 2, 3};` 执行完，发生了两件事：

```
array 这个变量里装着：一个地址 ──指向──> [1, 2, 3] 这份数据
```

调用 `changeArray(array)` 时，被复制的是**那个地址**。方法里的形参 `a` 和外部的 `array`
装着同一个地址，指向同一份数据。所以顺着 `a` 改 `a[0]`，改的就是外面那份数据：

```java
static void changeArray(int[] a) {
    a[0] = 99;   // 顺着钥匙打开的是外面那个房间
}
```

**打个比方**：方法调用时复制的是"钥匙"，不是"房间"。钥匙有两把，房间只有一个。
你用你那把钥匙把房间里的东西挪了，我拿我那把钥匙进去，看见的当然是挪过的样子。

### 2.3 那为什么 `reassignArray` 又不行？

因为那一行不是改房间里的东西，而是**换了一把新钥匙**：

```java
static void reassignArray(int[] a) {
    a = new int[] {7, 7, 7};   // 换了把新钥匙，外面那把没变
}
```

`a` 现在指向一个全新的数组了。可这是形参自己换钥匙，调用方那把钥匙还指着原来那个房间，
什么都没变。

**所以判断标准只有一句**：方法里到底动了"房间里的东西"，还是只动了"手里的钥匙"。

## 三、这条规矩在实战里长什么样

### 3.1 传可变对象 = 交出控制权

这是第 2.2 条最实际的后果：

```java
static void clearList(List<String> list) {
    list.clear();   // 调用方看得见
}
```

你把自己手里的钥匙给了别人，别人就能把你的房间清空。来看真实输出：

```terminal
========== 7. 传可变对象 = 交出控制权 ==========
方法把列表 clear 之后，调用方看到的 size = 0   ← 被掏空了
```

这不一定是坏事——很多 API 就是靠这个工作的。但你要**知道**自己交出去了。
如果不想交，传一个副本：

```java
someMethod(List.copyOf(myList));        // 对方再怎么 clear，动的是副本
someMethod(Arrays.copyOf(myArray, myArray.length));
```

`List.of(...)`、`Arrays.asList(...)` 也能防改，但要注意前者完全不可变，
后者**能 set 但不能 add/remove**——这个区别是集合那一课的事，先记住有这么回事。

### 3.2 这条线会一直延伸到多线程

你迟早会问：那多个线程同时改同一个数组怎么办？

答案是——**同一回事**。多个线程拿着指向同一份数据的钥匙，谁都能改，那就是第 13 课
要讲的线程安全问题。现在你手上有这个"钥匙和房间"的模型，到那节课会省很多力气。

## 四、重载：同名不同参，编译器按参数列表挑

一个类里可以有多个同名方法，只要**参数列表**不一样：

```java
public static String overload(int x)        { return "一个 int：" + x; }
public static String overload(int x, int y) { return "两个 int：" + x + "," + y; }
public static String overload(String s)     { return "一个 String：" + s; }
```

```terminal
========== 4. 重载：同名不同参，编译器按参数列表挑 ==========
overload(1)      → 一个 int：1
overload(1, 2)   → 两个 int：1,2
overload("ab")   → 一个 String：ab
```

编译器在**编译期**就根据你传的实参挑好了调哪个，运行期没有额外开销。

**关键点：只看参数列表，跟返回值无关。** 只有返回类型不同的两个方法，
在编译器眼里是同一个方法：

```terminal
$ javac -encoding UTF-8 -d out src/main/java/dev/javalearning/basics/methods/broken/ReturnTypeOnly.java
src/main/java/dev/javalearning/basics/methods/broken/ReturnTypeOnly.java:17: error: method twice(int) is already defined in class ReturnTypeOnly
    public long twice(int x) {   // ← 编译不过：twice(int) 已经被定义过了
                ^
1 error
```

`method twice(int) is already defined`——注意它说的是 `twice(int)`，
**参数列表一模一样，就是同一个方法**，返回类型不参与区分。

### 一个会让人愣一下的重载解析

我们同时有 `pick(int...)` 和 `pick(Integer)`，然后传一个 `1` 进去。你猜调哪个？

```terminal
pick(1) 选中了   → 单个 Integer（不是可变参数那个）
```

选中的是 `pick(Integer)`。规则是：**能不多给就不多给**——编译器优先选不需要
"打包成数组"的那个版本，`1` 自动装箱成 `Integer` 就满足了。

这条规则记住结论就行，细节属于编译原理。真正常见的场景是：

```java
println(int)      // 调这个
println(Object)   // 不是这个
```

## 五、可变参数：个数不定，本质上是个数组

```java
public static int sum(int... numbers) {
    int total = 0;
    for (int n : numbers) {
        total += n;
    }
    return total;
}
```

`int...` 的意思是"这里可以传 0 个或多个 int"。在方法体里，`numbers` 就是个普通数组：

```terminal
========== 5. 可变参数：个数不定，本质上是个数组 ==========
sum()           → 0
sum(1)          → 1
sum(1, 2, 3)    → 6
sum(already)    → 9   ← 数组可以直接传
```

三条值得记住：

1. **一个都不传是合法的**，此时拿到的是个长度为 0 的数组，不是 `null`
2. **可以直接把数组传进去**，因为它本来就是数组
3. **可变参数必须放在参数列表最后**，而且一个方法只能有一个

## 六、return：不只是"给值"

`return` 干两件事：**立刻结束这个方法**，以及（有返回类型时）**把一个值交回去**。

```java
public static String grade(int score) {
    if (score < 0) {
        return "成绩不合法";   // 提前溜走
    }
    if (score >= 90) {
        return "优秀";
    }
    return "及格";
}
```

```terminal
========== 6. return 在 String 方法里：提前溜走，不带值 ==========
grade(91) → 优秀
grade(75) → 及格
grade(-1) → 成绩不合法
```

`void` 方法里的 `return` 只干第一件事——提前结束：

```java
void process(String s) {
    if (s == null) {
        return;   // 不带值，直接走人
    }
    // 继续处理
}
```

用 `return` 提前溜走，比把整个逻辑套在一个巨大的 `if` 里可读得多。
这叫**卫语句**（guard clause），是让人少写嵌套的好习惯。

**一条容易忘的规则**：有返回类型的方法，编译器会检查"每条可能的路径都得有 return"。
像上面 `grade` 那样层层提前返回，最后必须有一个兜底的 `return`——漏了就是
`missing return statement`。

## 七、局部变量：活到花括号结束

方法里声明的变量叫局部变量（local variable），它的作用域到**声明它的那个花括号**结束：

```java
public static void scopeDemo() {
    {
        int inner = 1;
        System.out.println("内层花括号里 inner = " + inner);
    }
    // System.out.println(inner);   // 编译不过：离开了花括号就没了
    for (int i = 0; i < 1; i++) {
        System.out.println("for 里声明的 i = " + i);
    }
    // System.out.println(i);       // 同样编译不过
    System.out.println("（离开花括号，inner 和 i 都不存在了）");
}
```

```terminal
========== 8. 局部变量的作用域到花括号结束 ==========
内层花括号里 inner = 1
for 里声明的 i = 0
（离开花括号，inner 和 i 都不存在了）
```

上面那两行注释掉的代码是真编译不过的，我们把其中一行拿出来单独编译：

```terminal
$ javac -encoding UTF-8 -d out src/main/java/dev/javalearning/basics/methods/broken/OutOfScope.java
src/main/java/dev/javalearning/basics/methods/broken/OutOfScope.java:17: error: cannot find symbol
        System.out.println(inner);   // ← 编译不过：inner 只在上面那个花括号里活着
                           ^
  symbol:   variable inner
  location: class OutOfScope
1 error
```

`cannot find symbol`——出了花括号，这个变量**真的不存在了**，不是"看不见"，
是"没有"。这也解释了为什么 `for` 里声明的 `i` 在循环外不能再用。

## 八、不推荐的用法

- **别为了"省事"把方法写成 public static 到处调**——那是工具类（utility class）的做法，
  只适合纯函数（输入输出全靠参数，不依赖任何状态）。有状态的东西请做成对象的方法
- **别在条件表达式里写有副作用的调用**。[`&&` 的短路](./02-运算符与流程控制.md)会让右边的副作用不确定执行，方法调用同理；
  方法调用本身也是有副作用的表达式，同理——`if (list.size() > 0 && list.get(0).ok())`
  这种还行，但 `if (cache.get(key) != null)` 顺手在 `get` 里做了些别的，就是在埋雷
- **别用返回值 `null` 表示"没有结果"**——调用方很容易忘判，然后 NPE。
  这正是 [`Optional`](./08-Optional.md) 要解决的问题
- **别让一个方法干三件事**。`calculateAndSaveAndNotify()` 这种名字出现时，
  就是该拆的信号。一个方法只做一件事，名字才说得清

## 九、术语表

- **方法**（method）—— 一段有名字、可复用的逻辑；`main` 也是一个方法，只是它是入口
- **形参 / 实参**（parameter / argument）—— 声明时写的叫形参，调用时传的叫实参
- **值传递**（pass by value）—— 实参的值被复制一份交给形参；Java 只有这一种
- **重载**（overloading）—— 同名不同参，编译器按参数列表挑选
- **可变参数**（varargs）—— `int...`，方法体里当数组用，必须放最后
- **卫语句**（guard clause）—— 用提前 `return` 把特殊情况挡在外面，减少嵌套
- **局部变量**（local variable）—— 方法内声明，作用域到花括号结束
- **工具类**（utility class）—— 只有静态方法的类，通常还有私有构造器禁止 new
