先说一个真实场景。

你在写一个配置驱动的程序：要连哪个数据库、用哪个类去解析、调哪个方法，
全都写在 `application.properties` 里，运维改一行重启就生效。听起来很合理，
于是你写下这样的代码：

```java
String className = config.get("className");
Object obj = new className();          // ← 编译器：你说什么？
```

编译器不认识 `className` 这个名字，它只知道你有个变量叫 `className`。
**类名是运行时才知道的字符串，而 `new` 后面必须跟一个编译期就存在的类名。**

这就是这一课要解决的问题。反射（Reflection）就是那扇"运行时再决定"的后门。

## 一、先看常规访问：不用反射的时候

在讲反射之前，先明确它要替代的是什么。这一课的"教材类"是 [`User.java`](../src/main/java/dev/javalearning/reflection/User.java)，
故意把各种成员都放齐了——public / private / static 字段、static 初始化块、
两个构造器、public / private / 带参数的 private 方法、public static / private static 方法，
还有一个字段贴着自定义注解：

```java
public class User extends BaseEntity {

    public String name;                     // public 字段

    @Label("年龄")
    private int age;                        // private 字段 + 自定义注解

    private static int count;               // static 字段

    static {
        System.out.println("[User 的 static 块执行了 —— User 类被初始化了]");
    }

    public User() { this("匿名", 0); }       // 无参构造器
    public User(String name, int age) { ... } // 带参构造器

    public String hello() { ... }            // public 方法
    private String secret() { ... }          // private 方法
    private String greet(String p, int t) { ... }   // 带参数的 private 方法

    public static int getCount() { ... }     // public static 方法
    private static String internalCode() { ... }    // private static 方法

    @Override
    public String toString() {
        return "User(name=" + name + ", age=" + age + ")";
    }
}
```

`toString()` 是必须重写的：不写的话打印出来是 `User@1b6d3586` 这种带哈希值的字符串，
每次运行都不一样，文档里的输出就没法逐字复现了。这是[类与对象](./04-类与对象.md)里讲过的坑。

不反射的时候，用起来长这样：

```terminal
========== 1. 先看常规访问：直接 new、直接读、直接调 ==========
[User 的 static 块执行了 —— User 类被初始化了]
直接 new 出来的对象：User(name=小明, age=18)
直接读 public 字段 user.name = 小明
直接调 public 方法 user.hello() = 你好，我是 小明
通过类名读 static 方法 User.getCount() = 1
```

四行代码，四件事，全部**编译期就能检查**：

| 写法 | 编译器帮你确认了什么 |
|---|---|
| `new User("小明", 18)` | 这个构造器存在，参数类型和个数对得上 |
| `user.name` | `name` 是个 public 字段 |
| `user.hello()` | `hello()` 这个方法存在，返回值类型是什么 |
| `User.getCount()` | 这是静态方法，可以直接用类名调 |

**能编译期查出来的错误，绝不留到运行期**——这是判断"该不该用反射"的唯一标准。

那 private 成员呢？直接碰的话编译器当场就拦：

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/reflection/broken/ReadPrivateField.java
src/main/java/dev/javalearning/reflection/broken/ReadPrivateField.java:17: error: age has private access in User
        System.out.println(user.age);
                               ^
1 error
```

`age has private access in User`。这条错误在 [`ReadPrivateField.java`](../src/main/java/dev/javalearning/reflection/broken/ReadPrivateField.java) 里，
它在 `broken/` 包里，标红是正常的。

## 二、什么时候不够用：名字只在运行时才知道

常规访问有个前提：**你写代码的时候，就知道类名、字段名、方法名。**

但有些场景不满足这个前提。配置驱动的程序就是最典型的：连哪个数据库、用哪个解析类、
调哪个方法，全在配置文件里，改配置不用重新编译。

```java
Map<String, String> config = new LinkedHashMap<>();
config.put("className", "dev.javalearning.reflection.User");
config.put("methodName", "hello");
```

配置文件读进来就是一个 `Map<String, String>`，值都是字符串。你想拿它造对象：

```terminal
========== 2. 什么时候不够用：类名只在运行时才知道 ==========
配置文件里读到的是：{className=dev.javalearning.reflection.User, methodName=hello}
想造对象：new dev.javalearning.reflection.User()   ← 这行根本编译不过
想调方法：user.hello()   ← 同理，方法名也得写死
```

这是 demo 里"打印"出来的两行字，真实代码长这样：

```java
String className = config.get("className");
Object obj = new className();          // 编译错误：cannot find symbol
```

看看 `javac` 的原话：

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/reflection/broken/DynamicNew.java
src/main/java/dev/javalearning/reflection/broken/DynamicNew.java:27: error: cannot find symbol
        Object obj = new className();
                         ^
  symbol:   class className
  location: class DynamicNew
src/main/java/dev/javalearning/reflection/broken/DynamicNew.java:31: error: cannot find symbol
        obj.methodName();
           ^
  symbol:   method methodName()
  location: variable obj of type Object
2 errors
```

`cannot find symbol: class className`——编译器把 `className` 当成了一个类名去找，
当然找不到，因为它是个变量。方法名那行同理：`obj.methodName()` 被当成了"调一个叫
`methodName` 的方法"，而不是"调配置里写的那个方法"。

**这里大家思考一个问题**：编译器为什么不能通融一下？

因为 Java 是**静态类型语言**，编译期就要确定每个方法调用落在哪里、参数怎么传、返回值是什么类型。
`new className()` 里的 `className` 要到运行时才知道是什么，编译器就没法帮你检查
"这个构造器存在吗""参数对吗"——而这些恰恰是它存在的意义。

那有没有办法？有，但代价是**把检查从编译期挪到运行期**。这就是反射。

顺便记一个实现细节：`broken/DynamicNew.java` 里先 `String className = config.get(...)`
赋值给局部变量，再 `new className()`。这不是啰嗦，是为了让编译器报出清楚的那条错。
如果直接写成 `new config.get("className")()`，编译器会先卡在语法上，报 `';' expected`——
反而看不出真正的原因。

## 三、`Class` 对象：类的档案

反射的入口是一个叫 `Class` 的东西。它不神秘：**JVM 每加载一个类，就会为它建一个
`Class` 对象，这个对象里记着这个类的全部信息**——有哪些字段、哪些方法、哪些构造器、
父类是谁、贴了什么注解。

你可以把它理解成"这个类的档案"。有了档案，你就能在运行时查它、用它。

```terminal
========== 3. Class 对象：JVM 给每个类建的那份档案 ==========
User.class 就是 class dev.javalearning.reflection.User
它的类型是 java.lang.Class —— Class 自己也是个类
全限定名 getName() = dev.javalearning.reflection.User
简单名 getSimpleName() = User
父类 getSuperclass() = dev.javalearning.reflection.BaseEntity
是不是接口 isInterface() = false
同一个类只有一个 Class 对象：user.getClass() == User.class → true
```

两个要点：

1. **`Class` 自己也是个类。** 第二行 `User.class.getClass().getName()` 打出来是
   `java.lang.Class`——档案本身也有档案。这行看着像绕口令，但它说明 `Class` 不是关键字，
   就是个普通的类（不过它没有公开构造器，你造不出来，只能由 JVM 给你）。
2. **一个类只有一个 `Class` 对象。** 最后一行是 `true`。不管你怎么拿，拿到的都是同一份档案。

## 四、获取 `Class` 对象的三种方式（以及一个关键区别）

三种拿法，各有各的适用场合：

```java
Class<?> a = User.class;                              // ① 编译期就写死
Class<?> b = user.getClass();                          // ② 手里已经有实例
Class<?> c = Class.forName("dev.javalearning.reflection.User");  // ③ 运行时才决定
```

前两种一眼就懂，第三种是反射真正有用的那种——**字符串是运行时给的**。

但这里藏着一个很多人不知道的区别。看第 4 节的输出：

```terminal
========== 4. 获取 Class 对象的三种方式，以及一个关键区别 ==========
① 类名.class（编译期就写死）
   拿到了 dev.javalearning.reflection.HeavyInit，注意上面没有 static 块的输出
② 对象.getClass()（手里已经有实例时用）
   user.getClass() = dev.javalearning.reflection.User
③ Class.forName("全限定名")（运行时才决定加载谁）
  → [HeavyInit 的 static 块执行了：这个类被初始化了]
   拿到了 dev.javalearning.reflection.HeavyInit，上面那行 static 块输出就是证据
```

**①那行没有 `static` 块的输出，③那行有。** 这就是区别：

| 方式 | 触发类初始化吗 | 什么时候用 |
|---|---|---|
| `类名.class` | **不会** | 编译期就知道是哪个类 |
| `对象.getClass()` | 对象都造出来了，早初始化过了 | 手里已经有实例 |
| `Class.forName("全限定名")` | **会** | 名字是运行时给的字符串 |

### 4.1 为什么要在意"类有没有被初始化"

因为**类的初始化会执行 `static` 块**，而 `static` 块里可能有很重的活：
加载配置文件、建数据库连接池、初始化缓存……[类与对象](./04-类与对象.md)里讲过，
`static` 块一辈子只跑一次，就是这次。

所以"我只想看看这个类有什么字段，并不想真的用它"的时候，用 `.class` 而不是 `forName`，
可以避免误触发一堆初始化。这不是玄学，是能实测出来的。

为了演示这个区别，demo 里专门准备了一个从头到尾没被碰过的类
[`HeavyInit.java`](../src/main/java/dev/javalearning/reflection/HeavyInit.java)：

```java
public class HeavyInit {

    static {
        System.out.println("  → [HeavyInit 的 static 块执行了：这个类被初始化了]");
    }

    private HeavyInit() {
    }
}
```

它存在的唯一理由就是这个演示。`User` 在第 1 节已经被 `new` 过了，再拿它的 `Class`
看不出任何区别，所以必须有一个**干净**的类。

同一节的最后两行还证明了另一件事：

```terminal
三种方式拿到的是同一个 Class 对象吗：true（①②③ 指向的都是同一个类）
再 forName 一次，已经初始化过了，static 块不会再打：
   确实没再打 —— 一个类的初始化一辈子只发生一次
```

第二次 `Class.forName` 同一个类，`static` 块没再打。**初始化一辈子一次**，
所以 `.class` 的"不触发初始化"这个优势，只在"这个类还没被初始化过"的时候才有意义。

### 4.2 `forName` 抛的是受检异常

`Class.forName` 的签名里有个 `throws ClassNotFoundException`。它是**受检异常**
（checked exception），编译器要求你当场处理或者往外抛：

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/reflection/broken/UnhandledClassNotFound.java
src/main/java/dev/javalearning/reflection/broken/UnhandledClassNotFound.java:19: error: unreported exception ClassNotFoundException; must be caught or declared to be thrown
        Class<?> clazz = Class.forName("dev.javalearning.reflection.User");
                                      ^
1 error
```

这个异常来得有道理：**字符串是运行时给的，谁也不知道它拼得对不对。**
类名写错、类不在 classpath 上，都会抛它。这是反射的第一个代价——
编译器不再替你兜底了。反面教材在
[`UnhandledClassNotFound.java`](../src/main/java/dev/javalearning/reflection/broken/UnhandledClassNotFound.java)。

## 五、查看成员：`declared` 系列是个大坑

拿到 `Class` 对象之后，第一件事是看看它有什么。这里有一对方法名特别像、行为差很远：

| 方法 | 拿到的 |
|---|---|
| `getDeclaredFields()` | **本类**声明的所有字段（含 `private`），**不含父类** |
| `getFields()` | **只有 `public`**，但**含父类**的 |

一句话记法：**`declared` = 本类写的，不管权限；不带 `declared` = 公开的，包括继承来的。**
这两个维度是**交叉**的，这是最容易记混的地方。

看真实输出：

```terminal
========== 5. 查看成员：declared 系列和不带 declared 的区别 ==========
getDeclaredFields() 共 3 个（本类所有字段，含 private，不含父类）：
  private int age   ← 声明它的类是 User
  private static int count   ← 声明它的类是 User
  public String name   ← 声明它的类是 User
getFields() 共 2 个（只有 public，但含父类）：
  public long id   ← 声明它的类是 BaseEntity
  public String name   ← 声明它的类是 User
```

对比着看，两个方向都能看出来：

- `age` 和 `count` 是 `private`，**只在 `getDeclaredFields()` 里**；
- `id` 是父类 [`BaseEntity.java`](../src/main/java/dev/javalearning/reflection/BaseEntity.java) 声明的，
  **只在 `getFields()` 里**（因为它是 `public`）。

demo 里每行都打印了 `声明它的类是 XXX`，就是为了让"继承来的"一眼可辨。

方法那边同理，而且更明显：

```terminal
getDeclaredMethods() 共 6 个（本类的，含 private）：
  public static int getCount()   ← 声明它的类是 User
  private String greet(String, int)   ← 声明它的类是 User
  public String hello()   ← 声明它的类是 User
  private static String internalCode()   ← 声明它的类是 User
  private String secret()   ← 声明它的类是 User
  public String toString()   ← 声明它的类是 User
getMethods() 共 12 个（public，含父类，连 Object 的也算）：
  public boolean equals(Object)   ← 声明它的类是 Object
  public final native Class getClass()   ← 声明它的类是 Object
  public static int getCount()   ← 声明它的类是 User
  public native int hashCode()   ← 声明它的类是 Object
  public String hello()   ← 声明它的类是 User
  public final native void notify()   ← 声明它的类是 Object
  public final native void notifyAll()   ← 声明它的类是 Object
  public String toString()   ← 声明它的类是 User
  public final void wait()   ← 声明它的类是 Object
  public final void wait(long)   ← 声明它的类是 Object
  public final void wait(long, int)   ← 声明它的类是 Object
  public String whoAmI()   ← 声明它的类是 BaseEntity
```

`getMethods()` 那 12 个里，**有 8 个是 `Object` 的**（`equals` / `hashCode` / `getClass` /
`notify` / `notifyAll` / 三个 `wait` 重载），只有 3 个是 `User` 自己的，还有 1 个是父类的
`whoAmI()`。数一下上面那份列表就能对上：数到 `Object` 的行有 8 行。

**每次 `getMethods()` 都会捞到这一堆，写框架的时候要记得过滤**，
不然你扫"哪些方法需要处理"时会把 `wait()` 也扫进去。

构造器只有两个方法，没有"declared 的才含 private"这个复杂度以外的花样：

```terminal
getDeclaredConstructors() 共 2 个：
  public dev.javalearning.reflection.User()
  public dev.javalearning.reflection.User(String, int)
getConstructors() 共 2 个（只有 public 的）
```

`User` 的两个构造器都是 `public`，所以两边都是 2 个。想看区别得看第 7 节那个例子——
[`HeavyInit.java`](../src/main/java/dev/javalearning/reflection/HeavyInit.java) 的构造器是 `private` 的，
`getConstructors()` 返回 **0 个**，`getDeclaredConstructors()` 返回 **1 个**。

### 5.1 顺便说一句：返回顺序不保证

`getDeclaredMethods()` 返回的顺序，JDK 文档里**没有承诺**。同一个类在不同 JDK 上、
甚至同一次运行的不同时刻，顺序都可能不同。

demo 里那些输出是稳定的，因为我在打印前**自己排了序**：

```java
private static Method[] sortedMethods(Method[] methods) {
    Arrays.sort(methods, Comparator.comparing((Method m) -> m.getName())
            .thenComparingInt(Method::getParameterCount));
    return methods;
}
```

这是写"输出要稳定"的文档时必须做的一步。**别指望反射返回的顺序**，
要顺序就自己排。

## 六、操作成员：读、改、调

查完了就该动手了。`Field` 的 `get` / `set`，`Method` 的 `invoke`，就这三个动作。

```terminal
========== 6. 操作成员：读、改、调用 ==========
读 public 字段 field.get(user) = 小明
改完再读 = 小红，对象自己也变了：User(name=小红, age=18)
读 private 字段 → IllegalAccessException: class dev.javalearning.reflection.ReflectionDemo cannot access a member of class dev.javalearning.reflection.User with modifiers "private"
setAccessible(true) 之后 = 18
连 private 字段都能改：User(name=小红, age=20)
static 字段传 null 当对象也能读：count = 1
```

### 6.1 `field.get(obj)` 里的 `obj` 是什么

`get` 需要一个对象参数，因为字段属于某个具体对象。`field.get(user)` 就是"读 `user` 这个
对象的 `name` 字段"。

**改完对象自己也变了**——`field.set(user, "小红")` 不是改了个副本，改的就是 `user`。
这点和直接写 `user.name = "小红"` 完全一样。

### 6.2 private 字段真的会抛异常

这是很多人第一次用反射时最意外的一行：

```
IllegalAccessException: class dev.javalearning.reflection.ReflectionDemo
    cannot access a member of class dev.javalearning.reflection.User
    with modifiers "private"
```

**反射不是"绕过访问控制"，它只是"提供了另一条访问路径"，而这条路径照样受访问控制管。**
`private` 就是 `private`，反射拿到 `Field` 对象不代表你能读它。

要读，得显式申请：

```java
age.setAccessible(true);
System.out.println(age.get(user));   // 18
```

`setAccessible(true)` 的意思不是"把 `private` 改成 `public`"，而是**"调用时跳过访问检查"**。
字段本身的修饰符一点没变——这一点下面第九节还会用测试钉住。

### 6.3 `static` 成员传 `null` 当对象

```terminal
static 字段传 null 当对象也能读：count = 1
```

`count` 是 `static` 的，属于类不属于对象。既然不需要对象，那**对象参数传 `null` 就行**。

反过来，如果你硬传一个对象进去也不会错，只是那个对象毫无用处：

```java
count.get(null)        // 和
count.get(someUser)    // 结果完全一样
```

写测试钉这条的时候踩了个坑，值得记一笔：

```java
// 这样写会挂：expected 9 but was 10
assertThat(count.get(null)).isEqualTo(count.get(new User("路人", 0)));
```

原因是**参数从左往右求值**：左边先读到 `count` 是 9，然后 `new User(...)` 把
`count` 变成 10，右边读到 10，两边不一样。断言里的表达式把被断言的状态改了。
修法是先把对象造好，再比较——现在那条测试就是这么写的。

### 6.4 调方法：`invoke`

```terminal
调 public 方法 method.invoke(user) = 你好，我是 小红
调 private 方法 → IllegalAccessException: class dev.javalearning.reflection.ReflectionDemo cannot access a member of class dev.javalearning.reflection.User with modifiers "private"
setAccessible(true) 之后 = 这是 private 方法，外面本来调不到
带参数的 private 方法 greet("嗨", 3) = [嗨 嗨 嗨]
static 方法对象参数传 null：getCount() = 1
private static 方法同样传 null：internalCode() = 内部编号-1
```

`invoke` 的签名是 `Object invoke(Object obj, Object... args)`：

- 第一个参数是**在哪个对象上调**，`static` 方法传 `null`；
- 后面是**参数列表**，按顺序传，个数和类型都要对；
- 返回值永远是 `Object`，**原来是什么类型要自己强转**。

`private` 方法一样抛 `IllegalAccessException`，一样要靠 `setAccessible(true)`。

带参数的 `private` 方法有个额外步骤：找它的时候**要按参数类型找**：

```java
Method greet = User.class.getDeclaredMethod("greet", String.class, int.class);
greet.setAccessible(true);
greet.invoke(user, "嗨", 3);      // "嗨 嗨 嗨"
```

注意 `int.class` 不能写成 `Integer.class`。**反射是按精确签名找方法的**，
基本类型和包装类型算两个不同的签名。参数类型对不上，抛的是 `NoSuchMethodException`。

## 七、创建实例：`constructor.newInstance(args)`

反射造对象走 `Constructor`：

```terminal
========== 7. 创建实例：constructor.newInstance(args) ==========
无参构造器 newInstance() = User(name=匿名, age=0)
带参构造器 newInstance("小刚", 20) = User(name=小刚, age=20)
Class.newInstance() 从 Java 9 起就废弃了，统一走构造器
HeavyInit 的 getConstructors() = 0 个，getDeclaredConstructors() = 1 个
private 构造器直接 newInstance() → IllegalAccessException: class dev.javalearning.reflection.ReflectionDemo cannot access a member of class dev.javalearning.reflection.HeavyInit with modifiers "private"
setAccessible(true) 之后造出来了，类型是 HeavyInit
```

流程和调方法一模一样：**先找到构造器，再 `newInstance` 传参。**

```java
Constructor<?> withArgs = User.class.getDeclaredConstructor(String.class, int.class);
Object obj = withArgs.newInstance("小刚", 20);
```

顺带一个历史包袱：老代码里常见 `User.class.newInstance()`，它从 **Java 9 起就废弃了**
（deprecated）。原因是它只会调无参构造器，而且**把构造器抛的异常原样往外扔**，
调用方根本分不清是自己参数错了还是构造器里炸了。统一用 `getDeclaredConstructor()` +
`newInstance()` 就好。

`private` 构造器同样要 `setAccessible(true)`——`HeavyInit` 就是现成的例子。
这个技巧在写单例、写测试替身的时候很有用。

## 八、注解：贴在字段上的标签

注解（Annotation）是反射的另一半。**注解本身什么也不做，它只是"贴上去的一行数据"，
真正干活的是读它的那段反射代码。** 没有反射，注解就只是一堆注释。

自己写一个注解要两个元注解（贴在注解上的注解）：

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
public @interface Label {
    String value() default "";
}
```

完整代码在 [`Label.java`](../src/main/java/dev/javalearning/reflection/Label.java)。两个元注解的分工：

- `@Target(FIELD)` —— 限定它只能贴在字段上，贴错地方编译器会拦；
- `@Retention(RUNTIME)` —— **这条最关键**，决定了注解能不能活到运行时。

`@Retention` 有三个取值，默认是 `CLASS`：

| 取值 | 保留到哪 | 反射读得到吗 |
|---|---|---|
| `SOURCE` | 只留在源码里，编译就丢 | 读不到 |
| `CLASS` | 留在 class 文件里，但 JVM 不加载 | **读不到** |
| `RUNTIME` | 一直留到运行时 | 读得到 |

**默认值是 `CLASS`，不是 `RUNTIME`。** 这是个经典的坑：注解写了、编译过了、
跑起来不报错，就是读不出来。demo 第 8 节专门演示了这件事：

```terminal
========== 8. 注解：字段上贴的标签，运行时读得出来吗 ==========
age 上的 @Label = 年龄
name 上的 @Label = null（没贴就是 null）
@Label 有 @Retention(RUNTIME)，读到了 = 保留到运行时的标签
@ClassOnlyLabel 没写 @Retention，默认是 CLASS，读到 = null
没贴注解的字段读到 = null
```

四个数字分别对应四种情况：

1. `age` 上有 `@Label("年龄")`，`getAnnotation` 拿到了，`.value()` 是 `年龄`；
2. `name` 上什么也没贴，`getAnnotation` 返回 **`null`**；
3. 同一个类里那个贴了 `@Retention(RUNTIME)` 的字段，读得到；
4. 贴着没写 `@Retention` 的注解的字段，**也返回 `null`**——和第 2 种情况长得一模一样。

**第 4 条就是那个坑**：你以为注解没生效是因为"读法不对"，其实是注解根本没活到运行时。
这两种 `null` 光看结果是分不清的，所以**读注解之前必须先判空**：

```java
Label label = field.getAnnotation(Label.class);
if (label != null) {
    // 只有确实贴了才处理
}
```

demo 里那个 `@ClassOnlyLabel` 是故意写成"没有 `@Retention`"的：

```java
/** 故意不写 @Retention：默认是 CLASS，注解进了 class 文件但运行时读不到。 */
@interface ClassOnlyLabel {
}
```

"注解进了 class 文件但运行时读不到"这句话不是比喻，用 `javap` 看字节码能直接看到——
贴了 `@Retention(RUNTIME)` 的字段注解记在 `RuntimeVisibleAnnotations` 里，
没写的记在 `RuntimeInvisibleAnnotations` 里：

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/reflection/ReflectionDemo.java
$ javap -v -p -cp out 'dev.javalearning.reflection.ReflectionDemo$Labeled'
  private java.lang.String runtimeField;
    descriptor: Ljava/lang/String;
    flags: (0x0002) ACC_PRIVATE
    RuntimeVisibleAnnotations:
      0: #12(#13=s#14)
        dev.javalearning.reflection.Label(
          value="保留到运行时的标签"
        )

  private java.lang.String classField;
    descriptor: Ljava/lang/String;
    flags: (0x0002) ACC_PRIVATE
    RuntimeInvisibleAnnotations:
      0: #17()
        dev.javalearning.reflection.ReflectionDemo$ClassOnlyLabel
```

两个注解**都老老实实写进了 class 文件**，区别只在 JVM 加载时认不认那一栏。
`RuntimeInvisible` 那栏 JVM 直接跳过，所以 `getAnnotation` 只能返回 `null`。

这种"编译通过、运行不报错、结果静默不对"的坑，比抛异常难查得多——
因为它安静得像什么都没发生。

## 九、反射的代价与风险

### 9.1 代价一：错误从编译期挪到了运行期

这是最贵的一条。看输出：

```terminal
========== 9. 反射的代价与风险 ==========
字段名拼错 getDeclaredField("nmae") → NoSuchFieldException: nmae
方法名拼错 getDeclaredMethod("helo") → NoSuchMethodException: dev.javalearning.reflection.User.helo()
注意：这两行编译期一声不吭，写完代码看不出来，跑起来才炸
```

`"nmae"` 拼错了 `name`。直接写 `user.nmae` 的话，编译器立刻标红；写成
`getDeclaredField("nmae")` 就是一个**普普通通的字符串**，编译器没有任何理由拦你。

代价还不止"发现得晚"，还有"发现得晚在什么地方"：

- 直接调用拼错，是**编译失败**，你根本发不出去；
- 反射拼错，是**运行时抛异常**。如果你的代码路径正好没被测试覆盖，
  它可能在生产环境第一次执行到那一行时才炸。

所以反射代码的测试覆盖率要求，比普通代码高得多。

### 9.2 代价二：性能

反射比直接调用慢，这是真的。跑 [`ReflectionCost.java`](../src/main/java/dev/javalearning/reflection/ReflectionCost.java) 看：

```terminal
$ java src/main/java/dev/javalearning/reflection/ReflectionCost.java
[User 的 static 块执行了 —— User 类被初始化了]
第 1 轮：直接 137.5 ms，反射 172.3 ms
第 2 轮：直接 198.4 ms，反射 130.6 ms
第 3 轮：直接 80.3 ms，反射 220.7 ms
第 4 轮：直接 232.7 ms，反射 174.2 ms
第 5 轮：直接 105.7 ms，反射 213.4 ms
第 6 轮：直接 149.0 ms，反射 312.5 ms

取各边最快的一轮（调用 5000000 次 user.hello()）：
  直接调用：80.3 ms
  反射调用：130.6 ms
  反射大约是直接调用的 1.6 倍

换算成每次调用：
  直接调用：16 纳秒
  反射调用：26 纳秒

（每次运行数字都不同，看量级：反射确实更慢，但慢的是几十纳秒这个级别）
```

上面是**某一次真实运行**的完整输出。这一课的其它终端块都能逐字复现，**只有这一块不行**——
耗时天生不稳定，你自己跑出来的数字一定和上面不一样，这是正常的。

**这组数字每次运行都不一样**，所以它没有被塞进 demo 的主输出里（那会让输出不稳定，
文档就没法逐字复现了）。看量级：这次是 1.6 倍，多跑几次会在 1.5～2.5 倍之间晃。

慢在哪？反射调用时 JVM 无法内联（inline）、无法做那些基于"编译期就知道调的是谁"的优化，
而且参数要装箱成 `Object[]`、返回值要强转回来。

但我想说的是另一件事：**看绝对值，慢的是几十纳秒。**
如果一个反射调用发生在"应用启动时扫一遍注解"，那完全无所谓；
如果发生在每秒百万次的热点路径里，那就是灾难。

**写这个对比时踩了两个坑，比结论本身更值得记：**

**坑一：不消费结果，JIT 会把整个循环优化掉。**

第一版写的是这样：

```java
for (int i = 0; i < ROUNDS; i++) {
    user.hello();
}
```

测出来直接调用的耗时是 **0 ms**。不是它快到测不出来，是 JIT 发现这个循环白算，
直接把整段删了。修法是加一个"黑洞"把结果攒起来：

```java
private static long sink;

for (int i = 0; i < ROUNDS; i++) {
    sink += user.hello().length();   // 结果被用到了，删不掉
}
```

**坑二：只测一轮，谁先被 JIT 编译谁吃亏。**

第一版只测一轮，数字能差几十倍（我看过 1.4 倍到 85 倍都有）。因为第一轮跑的时候
代码还没被 JIT 编译成机器码，测的是"解释执行"的速度。

修法是**预热 + 多轮取最小值**：

```java
for (int i = 0; i < WARMUP; i++) {          // 先跑热，让 JIT 编译
    sink += user.hello().length();
    sink += ((String) hello.invoke(user)).length();
}
// 然后两边各测 TRIES 轮，取各自最快的一轮
```

即便如此，这仍然**不是**一个严谨的基准测试（JMH 才是正经工具）。
它的价值在于告诉你"量级差多少"，而不是"精确差多少"。

### 9.3 代价三：封装被打破

`setAccessible(true)` 一开，`private` 就形同虚设。测试里钉了这条：

```java
User user = new User("小明", 18);
Field age = User.class.getDeclaredField("age");
age.setAccessible(true);
age.set(user, -999);                    // 没有任何校验能拦住
```

`-999` 这个年龄当然不合理，但 `User` 的构造器校验不了它——因为它是绕过构造器直接塞进去的。
**封装的意义是"这个类保证自己的状态总是合法的"，而反射能让这个保证失效。**

### 9.4 那为什么框架离不开它

因为**框架写出来的时候，你的类还不存在**。

Spring 要给你注入依赖，它得在运行时看你哪个字段标了 `@Autowired`——那个字段名是几个月后
别人写的。JUnit 要跑你的测试，它得在运行时找出哪些方法标了 `@Test`——那些方法是别人写的。
JSON 库要把对象转成 JSON，它得在运行时遍历你的字段——那些字段它编译时根本没见过。

**所有"处理别人的代码"的工具，都只能靠反射。** 这不是偷懒，是唯一的选择。

测试里模拟了一遍这个套路：

```java
// 模拟 JUnit 找 @Test 方法、Spring 找 @Autowired 字段的做法
List<String> labeled = Arrays.stream(User.class.getDeclaredFields())
        .filter(f -> f.isAnnotationPresent(Label.class))
        .map(Field::getName)
        .toList();      // ["age"]
```

扫一遍、按注解过滤、取出需要的——框架干的核心事情，就这么点。

## 十、不推荐的用法

- **能用直接调用就别用反射。** 编译器能替你查的错，别主动放弃。
  `user.hello()` 永远比 `method.invoke(user)` 好：快、类型安全、重构工具能改名
- **别用反射写业务逻辑。** 反射适合"处理未知的类"，不适合"我懒得写 getter"。
  业务代码里出现 `Class.forName` 通常意味着设计出了问题
- **`setAccessible(true)` 别滥用。** 它只是关掉检查，不是把 `private` 变成 `public`。
  一旦开了，那个类的封装承诺就不作数了，而且**它可能被未来的 JDK 拦住**——
  模块系统（JPMS）下跨模块访问别人的私有成员会抛 `InaccessibleObjectException`。
  这不是理论：想改 `String` 内部的 `value` 字段，JDK 25 上就是这个下场
  （下面这段是我随手写个临时类试出来的，不在仓库里）：

  ```
  java.lang.reflect.InaccessibleObjectException: Unable to make field private final
  byte[] java.lang.String.value accessible: module java.base does not "opens java.lang"
  to unnamed module @4ba2ca36
  ```

  `module java.base does not "opens java.lang"`——JDK 自己就是最大的那个"不让你碰"的库。
  注意 message 末尾那个 `@4ba2ca36` 是模块哈希，**每次都不同**，所以这类信息不适合往文档里贴
- **别在热点路径里用反射。** 启动时扫一遍注解没问题，每秒百万次调用就是灾难。
  真要高频用，把 `Method` / `Field` 对象缓存起来（别每次 `getDeclaredMethod`），
  或者用 `MethodHandle` / `LambdaMetafactory` 这些更快的路子
- **别依赖反射返回的顺序。** `getDeclaredMethods()` 的顺序没有承诺，
  要稳定就自己排序
- **`getMethods()` 记得过滤 `Object` 的方法。** 它会把 `wait` / `notify` / `equals`
  一起给你，扫方法时不过滤就会莫名其妙处理到它们
- **读注解前先判空。** 没贴注解返回 `null`，没写 `@Retention(RUNTIME)` 也返回 `null`，
  直接 `.value()` 就是 `NullPointerException`

## 十一、这一课的术语表

- **反射**（Reflection）—— 在运行时查看类的结构、创建对象、读写字段、调用方法
- **`Class` 对象**—— JVM 为每个加载的类建的"档案"，一个类只有一份
- **类字面量**（class literal）—— `User.class` 这种写法，编译期确定，不触发类初始化
- **类初始化**（class initialization）—— 执行 `static` 字段赋值和 `static` 块，一个类一辈子一次
- **`Class.forName`**—— 用字符串动态加载类，**会**触发类初始化，抛受检的 `ClassNotFoundException`
- **`declared` 系列**—— `getDeclaredXxx()` 只看本类，含 `private`，不含父类
- **`getFields` / `getMethods`**—— 只看 `public`，但含父类和 `Object` 继承来的
- **`Field` / `Method` / `Constructor`**—— 反射里代表字段、方法、构造器的三个类
- **`setAccessible(true)`**—— 跳过访问检查，不是改修饰符；模块系统下可能失效
- **`IllegalAccessException`**—— 碰了没有权限的成员时抛的异常，`setAccessible` 能解
- **`NoSuchFieldException` / `NoSuchMethodException`**—— 名字或签名找不到，运行时才抛
- **注解**（annotation）—— 贴在代码上的一行数据，本身不干活，靠反射读
- **元注解**（meta-annotation）—— 贴在注解上的注解，如 `@Retention` / `@Target`
- **`@Retention(RUNTIME)`**—— 让注解活到运行时，**不写默认是 `CLASS`，反射读不到**
- **`@Target`**—— 限定注解能贴在什么地方（字段、方法、类……）
- **内联**（inlining）—— JIT 把方法调用替换成方法体，反射调用会妨碍它
- **JPMS**—— Java 模块系统，会给反射的跨模块访问加上限制

## 十二、下一课

反射是"运行时才决定"的极致：类名是字符串、方法名是字符串，什么都能在最后一刻拼出来。

但你可能已经感觉到，这一课的代码不好看：异常要一层层处理，返回值要强转，
`setAccessible` 到处写。**而且它慢。**

下一课换个方向。前面几课我们一直在写"怎么做"——`for` 循环、`if` 判断、
一行行告诉计算机先干什么再干什么。下一课要问的是：

> **如果我只想描述"我要什么"，把"怎么做"交给库去决定呢？**

这就是 [Stream](./10-Stream.md)，用声明式取代 `for` 循环。

下期再见。
