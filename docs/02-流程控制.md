# 02 · 流程控制

Java 程序默认从上往下、从左往右执行。想改变这个顺序，你只有三类手段：

| 手段 | 回答的问题 | 用什么 |
|---|---|---|
| **选择** | 走哪一条路？ | `if`、`switch`、三目 |
| **重复** | 这段代码怎么跑多次？ | `for`、`while`、增强 for |
| **跳转** | 怎么提前离开当前位置？ | `break`、`continue`、`return` |

这一章就按这三类走。读完之后你会发现，很多看起来零散的语法点
（短路、穷尽匹配、标签）都能归到这三格里。

## 怎么跑这一章

```bash
./gradlew test --tests '*ControlFlowTest'
./gradlew test --tests '*ControlFlowExercisesTest'
```

# 一、选择

## 为什么 `s != null && s.length() > 0` 不会炸？

这是 Java 里最常见的一行代码，也是最值得先想明白的一行。

问题在于 `s.length()` 会在 `s` 是 `null` 时抛 `NullPointerException`。
那为什么把 `s != null` 写在前面就没事？

```java
String s = readName();     // 可能是 null

if (s != null && s.length() > 0) {
    // 走进来时，s 一定不是 null
}
```

`&&` 有个**短路**特性：如果左边已经是 `false`，右边根本不会执行。
`&&` 左边为 `false` 时整条表达式必然是 `false`，右边算不算都改变不了结论，
所以 Java 直接不算是省事。`||` 同理，左边已经是 `true` 时右边跳过。

于是 `s` 是 `null` 时：左边 `s != null` 得 `false`，整条短路，右边那句
`length()` 根本没机会执行，异常也就不会发生。

顺序反过来就一定会炸：

```java
if (s.length() > 0 && s != null) {   // s 为 null 时，第一句就抛异常了
```

**结论**：`&&` 左边的条件越"安全"越要放前面——它同时也是一道保护门。

验证：`ControlFlowTest.Choosing#andSkipsTheRightSide`、
`ControlFlowTest.Choosing#orSkipsTheRightSide`

## 短路不是免费的：副作用会被跳过

短路意味着**右边的表达式可能一次都不跑**。如果右边有副作用，两种写法结果会不同：

```java
int i = 3;
boolean r = (i++ > 0 || i++ > 0);    // r 为 true，i 变成 4：左边已经 true，右边被跳过
```

换成单个竖线（**非短路**的"或"），右边一定会执行：

```java
int j = 3;
boolean s = (j++ > 0 | j++ > 0);     // s 为 true，j 变成 5：两边都跑了
```

两个表达式的逻辑结果都是 `true`，但 `i` 和 `j` 的差别说明了一件事：
**只要表达式里有副作用，就要清楚知道它会不会被执行。**
`&` 和 `|` 是 Java 提供的非短路版本，主要用于位运算；
写普通业务逻辑时几乎不会用到它们。

验证：`ControlFlowTest.Choosing#bitwiseOrAlwaysEvaluatesBothSides`

## 漏写 `break` 会发生什么？

传统 `switch` 按顺序往下匹配，一旦匹配上就**从那里一直执行到底**，
除非遇到 `break` 或 `}`。这叫 fall-through。

```java
int grade = 4;
int sum = 0;
switch (grade) {
    case 4:
        sum += 4;
        // 这里忘了写 break
    case 3:
        sum += 3;      // 也会执行
        break;
    default:
        sum += 0;
}
// sum 是 7，不是 4
```

从语法上讲这完全合法——多个 case 共享一段代码本来就是有意设计的用法，
所以编译器不会拦你。代价是读代码的人（或你自己三个月后）会以为
只处理了一个分支。

## switch 表达式：让编译器帮你检查

Java 14 起有箭头语法，形态是「一个产生结果的表情」而不是「一段控制语句」：

```java
String label = switch (grade) {
    case 4 -> "优秀";
    case 3 -> "良好";
    case 2 -> "及格";
    default -> "待改进";
};
```

多个值共享一个分支用逗号，需要多行逻辑时用 `yield`：

```java
int score = switch (grade) {
    case 4 -> 95;
    case 3 -> {
        int bonus = 5;
        yield bonus + 85;      // 必须显式 yield
    }
    default -> 60;
};
```

### 什么时候可以省掉 `default`？

这是个容易踩的分叉：**取决于 switch 的参数类型是不是"封闭"的**。

参数是 `int` 时必须写 `default`。`int` 有无穷多个取值，
编译器无法证明你覆盖完了，所以省掉就编译报错：

```java
String f(int x) {
    return switch (x) {
        case -1 -> "neg";
        case 0  -> "zero";
        case 1  -> "pos";
        // 编译器报：the switch expression does not cover all possible input values
    };
}
```

参数是**枚举**时就不用写。所有取值都在枚举里列着，编译器能逐个核对：

```java
enum DayOfWeek { MONDAY, TUESDAY, ..., SATURDAY, SUNDAY }

String typeOf(DayOfWeek day) {
    return switch (day) {
        case MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY -> "工作日";
        case SATURDAY, SUNDAY -> "休息日";
        // 没有 default。以后往枚举里加一个新值，这里立刻编译报错
    };
}
```

这个差别直接影响你什么时候会发现漏分支：枚举是**编译期**，
`int` 则要等到线上跑到那个没覆盖的取值才会抛 `MatchException`。

> 上一版文档把 `Integer.signum` 当成"小枚举"来说明穷尽性，那是错的：
> 它返回 `int`，所以照样必须写 `default`。能省掉 `default` 的只有真正的枚举。

验证：`ControlFlowTest.Choosing#classicSwitchFallsThroughWhenBreakIsMissing`、
`ControlFlowTest.Choosing#switchExpressionOnIntNeedsDefault`、
`ControlFlowTest.Choosing#switchExpressionOnEnumIsExhaustive`

## 三目运算符：两个分支类型不一样会怎样

```java
long value = flag ? 1 : 2L;     // OK，结果类型被提升成 long
int  bad   = flag ? 1 : 2L;     // 编译报错：long 不能隐式缩回 int
```

规则和第 1 章的 `byte` 提升一样：两个分支类型不一致时，统一提升到更宽的那个。
反过来要变窄必须显式转换。

验证：`ControlFlowTest.Choosing#ternaryPromotesToTheWiderType`

# 二、重复

## for 的三段式

```java
int sum = 0;
for (int i = 0; i < 5; i++) {
    sum += i;
}
// sum 是 10（0+1+2+3+4）
```

三段分别是「初始化」「条件」「更新」。三个部分都可以省略，
所以下面几种都合法：

```java
for (;;) { }                     // 死循环
for (; i < n; i++) { }           // 沿用外层的 i
for (int i = 0; i < n; ) { i++; }  // 更新挪进循环体
```

## while 和 do-while 差在哪一步

唯一的区别是**判断条件的时机**：

```java
int i = 5;

// while：先判断，后执行。条件一开始就假，循环体一次都不进
int count = 0;
while (i < 3) { count++; }      // count == 0

// do-while：先执行，后判断。哪怕条件一开始就假也一定跑一次
count = 0;
do { count++; } while (i < 3);  // count == 1
```

选哪个：确定要跑至少一次就用 `do-while`，否则用 `while`。
如果不确定，`while` 更贴近"先检查再动作"的习惯。

验证：`ControlFlowTest.Repeating#forLoopHasThreeParts`、
`ControlFlowTest.Repeating#whileAndDoWhileDifferOnWhenTheyCheck`

## 为什么在增强 for 里删元素会崩？

```java
List<Integer> numbers = new ArrayList<>(List.of(1, 2, 3, 4));

for (int x : numbers) {
    if (x % 2 == 0) {
        numbers.remove(x);       // ConcurrentModificationException
    }
}
```

增强 for 的底层是 `Iterator`，而 `Iterator` 有一条约定：
**迭代过程中不改变集合的结构**（增、删都算）。
删掉一个元素后，后面的元素索引整体前移，迭代器手里记的位置就对不上了，
所以 `ArrayList` 的实现会在这次操作时抛出 `ConcurrentModificationException`。

要删就用 `removeIf`：

```java
numbers.removeIf(n -> n % 2 == 0);   // 剩 [1, 3]
```

`removeIf` 自己管理遍历过程，不违反上面那条约定，所以能安全地删。

验证：`ControlFlowTest.Repeating#removingWhileIteratingThrows`、
`ControlFlowTest.Repeating#removeIfIsTheSafeWayToDelete`

## 顺手一个陷阱：`remove(2)` 删的不是 2

`List` 有两个都叫 `remove` 的方法：

```java
remove(int index)       // 按下标删
remove(Object element)  // 按值删
```

传 `int` 会选到前一个（`int` 比 `Integer` 更精确匹配），
所以删的是**下标 2 那个元素**，不是值为 2 的元素：

```java
List<Integer> a = new ArrayList<>(List.of(1, 2, 3, 4));
a.remove(2);                  // 删掉下标 2，也就是值 3 → 剩 [1, 2, 4]

List<Integer> b = new ArrayList<>(List.of(1, 2, 3, 4));
b.remove(Integer.valueOf(2)); // 删掉值为 2 的元素      → 剩 [1, 3, 4]
```

增强 for 里的 `x` 是 `int`，所以 `numbers.remove(x)` 走的是按下标那个重载。
就算改成 `Integer.valueOf(x)` 避开重载歧义，在增强 for 里依然会抛
`ConcurrentModificationException`——那是另一个问题。

验证：`ControlFlowTest.Repeating#removeHasTwoOverloadsAndIntPicksTheIndexOne`

## 增强 for 里的变量改不回集合

```java
List<Integer> numbers = new ArrayList<>(List.of(1, 2, 3));
for (Integer x : numbers) {
    x = x * 10;               // 改的是局部变量 x
}
numbers                        // 还是 [1, 2, 3]
```

`x` 是集合里那个元素的一份引用副本。你改的是副本的指向，
不是集合里那个引用。要真正写回去得用 `set`：

```java
for (int i = 0; i < numbers.size(); i++) {
    numbers.set(i, numbers.get(i) * 10);
}
```

验证：`ControlFlowTest.Repeating#enhancedForCannotWriteBack`

# 三、跳转

## continue 只跳过这一次

```java
int handled = 0;
for (int i = 1; i <= 10; i++) {
    if (i % 5 == 0) {
        continue;              // i 为 5 和 10 时跳过本轮
    }
    handled++;
}
// handled == 8
```

`continue` 结束的是**当前这一轮**，循环本身继续。
`break` 则是结束整个循环。

## break 只能跳出一层

```java
int visited = 0;
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (j == 2) break;     // 只跳出内层，外层继续
        visited++;
    }
}
// visited == 6：三轮外层，每轮跑 2 次内层
```

## 标签：想跳多层时

```java
int visited = 0;
outer:                          // 标签贴在语句前面
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (j == 2) break outer; // 连外层一起结束
        visited++;
    }
}
// visited == 2
```

语法是 `名字:` 贴在语句前，然后用 `break 名字` 或 `continue 名字`。
Java 没有 `goto`，标签是这里唯一的手段。

日常业务代码里用得不多，因为多数情况下有更清楚的做法：
**把内层循环抽成一个方法，在那个方法里 `return`**。
一层循环自然就结束了，读代码的人也更容易看出循环的边界在哪。

验证：`ControlFlowTest.Jumping#continueSkipsOnlyTheCurrentIteration`、
`ControlFlowTest.Jumping#plainBreakExitsOnlyTheInnermostLoop`、
`ControlFlowTest.Jumping#labeledBreakExitsTheOuterLoop`

## 本章要点

- 改变执行顺序只有三类手段：选择、重复、跳转
- `&&` / `||` 会短路，右边可能不执行。有副作用时要留意
- `&` / `|` 是非短路版本，两边都会跑
- 传统 switch 漏 `break` 会 fall-through；switch 表达式用箭头语法
- switch 处理 `int` 必须写 `default`，处理**枚举**才可以省
- `while` 先判断，`do-while` 先执行
- 迭代期间改变集合结构会抛 `ConcurrentModificationException`，删除用 `removeIf`
- `List.remove(int)` 按下标删，`remove(Object)` 按值删
- `break` 只跳一层，标签能跳多层——但更好的办法是抽方法 + `return`
