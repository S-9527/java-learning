# 02 · 流程控制

看完你应该能解释这些现象：

- 为什么 `s != null && s.length() > 0` 不会抛 `NullPointerException`
- 为什么 `switch` 写漏 `break` 编译器不拦你，但 `yield` 写漏了会拦
- `break` 能不能跳出两层循环

## 短路求值：`&&` 和 `||` 不只是逻辑运算

`&&` 左边为 `false` 时，**右边根本不会执行**。`||` 左边为 `true` 时同理。

`ControlFlowTest.ShortCircuit#andDoesNotEvaluateTheRightSide`、
`ControlFlowTest.ShortCircuit#orDoesNotEvaluateTheRightSide`

```java
false && wouldThrowIfEvaluated()   // 右边不跑，返回 false
true  || wouldThrowIfEvaluated()   // 右边不跑，返回 true
```

这就是 Java 里 null 安全检查的标准写法：

`ControlFlowTest.ShortCircuit#nullCheckGuardsTheDereference`

```java
if (s != null && s.length() > 0) {   // 短路：s 为 null 时不会碰第二段
    ...
}
```

> 顺序不能反。写成 `s.length() > 0 && s != null` 就会在 `s` 为 null 时炸掉。

反过来，当你想让**两边都必须执行**时，用单独的非短路运算符
`&`（与）和 `|`（或）：

```java
if (validate(a) & validate(b)) {   // 两个 validate 一定都会跑
    ...
}
if (validate(a) && validate(b)) {  // validate(b) 只在 validate(a) 为 true 时才跑
    ...
}
```

日常写业务代码几乎不需要 `&`/`|`，它们主要用于位运算。但知道「两边都会跑」
这一点，能解释为什么 `i++ > 0 || i++ > 0` 这种代码会把 `i` 加两次。

## switch：旧写法和新写法差很多

### 传统 switch 语句

`ControlFlowTest.Switches#classicSwitchFallsThroughWhenBreakIsMissing`

```java
int grade = 4;
int sum = 0;
switch (grade) {
    case 4:
        sum += 4;
        // 忘了写 break
    case 3:
        sum += 3;
        break;
    default:
        sum += 0;
}
sum     // 7，不是 4
```

漏 `break` 会**静默串到下一个 case**。编译器不报错，因为从语法上讲这完全合法
（这叫 fall-through，本来就是有意设计的能力，比如 `case 1: case 2: doSomething(); break;`）。

坑在于：你以为它只处理了一个分支，实际处理了好几个。
`ControlFlowExercisesTest#exerciseSwitchFallThroughResult` 是练这个。

### switch 表达式（推荐）

Java 14 起支持箭头语法，不用 `break`、不用冒号、可以当返回值用。

`ControlFlowTest.Switches#switchExpressionReturnsDirectly`

```java
String label = switch (grade) {
    case 4 -> "优秀";
    case 3 -> "良好";
    case 2 -> "及格";
    default -> "待改进";
};
```

优势：

1. **漏写分支编译报错**。用 `Integer.signum` 这类小枚举时，连 `default` 都能省——
   编译器知道所有可能值，你漏一个分支它就报错。`ControlFlowTest.Switches#switchExpressionIsExhaustiveOverEnum`
2. 每个分支必须产生值，不可能「什么都不做」
3. 一眼能看出这是一个产生结果的表达式，而不是一段控制语句

多个值共享一个分支，用逗号：

```java
switch (day) {
    case MONDAY, FRIDAY -> "工作日";
    case SATURDAY, SUNDAY -> "休息日";
    default -> "—";
}
```

需要复杂逻辑时用 `yield`：

```java
int score = switch (grade) {
    case 4 -> 95;
    case 3 -> {
        int bonus = 5;          // 这里可以写任意语句
        yield bonus + 85;       // 但必须显式 yield
    }
    default -> 60;
};
```

## 三种循环

### for：条件为假时一次都不进

`ControlFlowTest.Loops#forLoopHasThreeParts`

```java
int sum = 0;
for (int i = 0; i < n; i++) {
    sum += i;
}
```

三段式：初始化、条件、更新。三个部分都可以省略，所以下面几种都合法：

```java
for (;;) { }                    // 死循环
for (; i < n; i++) { }          // 沿用外层的 i
for (int i = 0; i < n; ) { i++; } // 更新挪到循环体里
```

### while 和 do-while 的区别

这是唯一的关键区别：**什么时候判断条件**。

`ControlFlowTest.Loops#whileAndDoWhileDifferOnTheFirstCheck`

```java
int i = 5;

// while：先判断，后执行
while (i < 3) { count++; }      // count == 0，一次都不进

// do-while：先执行，后判断
do { count++; } while (i < 3);  // count == 1，至少跑一次
```

选哪个：确定要跑至少一次用 `do-while`，否则用 `while`。
新手建议默认全用 `while`，因为它符合「先检查再动作」的直觉。

## break、continue 和标签

`ControlFlowTest.Loops#continueSkipsOnlyTheCurrentIteration`

- `continue` —— 跳过**本次**剩余部分，进入下一轮
- `break` —— 跳出**当前这一层**循环

```java
for (int i = 1; i <= 10; i++) {
    if (i % 5 == 0) {
        continue;    // i 为 5 和 10 时跳过
    }
    handled++;       // 实际执行 8 次
}
```

### break 只跳一层

`ControlFlowTest.Loops#breakExitsOnlyTheInnermostLoop`

```java
int visited = 0;
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (j == 2) break;    // 只跳出内层，外层继续
        visited++;
    }
}
// visited == 6：三轮外层 × 每轮 2 次内层
```

### 标签能跳多层

`ControlFlowTest.Loops#labeledBreakExitsTheOuterLoop`

```java
int visited = 0;
outer:                    // 标签贴在循环前面
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        if (j == 2) break outer;    // 连外层一起结束
        visited++;
    }
}
// visited == 2
```

标签语法是 `名字:` 贴在语句前面，然后用 `break 名字` / `continue 名字`。
Java 没有 C 那样的 `goto`，标签是唯一能实现类似效果的办法。
`ControlFlowExercisesTest#exerciseLabeledBreakVisits` 是练这个。

## 增强 for 不能改集合

`ControlFlowTest.EnhancedFor#enhancedForCannotWriteBack`

```java
List<Integer> numbers = new ArrayList<>(List.of(1, 2, 3));
for (Integer x : numbers) {
    x = x * 10;     // 只改了局部变量 x，集合里的元素没动
}
numbers   // 还是 [1, 2, 3]
```

原因：`x` 是集合里那个元素的一份**引用副本**。你改的是副本指向的绑定，
不是集合里的那个引用。`Integer` 不可变所以这里尤其安全，但换成 `StringBuilder`
这类可变对象，`x.append(...)` 会真的改到集合里的内容——这更让人意外。

### 要删元素请用 removeIf

`ControlFlowTest.EnhancedFor#removeIfIsTheSafeWayToDelete`

```java
numbers.removeIf(n -> n % 2 == 0);   // 安全
```

反例：

```java
for (int i = 0; i < numbers.size(); i++) {
    if (numbers.get(i) % 2 == 0) {
        numbers.remove(i);           // 删完索引前移，会漏掉元素
        i--;                         // 得手动补一刀
    }
}

for (int x : numbers) {
    if (x % 2 == 0) {
        numbers.remove(x);          // 直接抛 ConcurrentModificationException
    }
}
```

增强 for 的底层是 `Iterator`，而 `Iterator` 有一条铁律：
**迭代过程中不允许结构性修改集合**。`removeIf` 不违反这条，所以它安全。
`ControlFlowExercisesTest#exerciseEnhancedForCannotWriteBack` 是练这个。

## 三目运算符的类型规则

`ControlFlowTest.Ternary#ternaryPromotesToTheWiderType`

```java
long value = true ? 1 : 2L;    // OK：结果类型提升成 long
int  bad   = true ? 1 : 2L;    // 编译报错：long 不能隐式缩回 int
```

规则和第 1 章的 byte 提升一样：两个分支类型不一致时，统一提升到更宽的那个。
反过来要变窄必须显式转换：`ControlFlowTest.Ternary#ternaryRequiresAnExplicitCastToNarrow`。

## 本章要点

- `&&` / `||` 短路，这是 null 安全检查的基础
- `&` / `|` 不短路，两边都跑
- 传统 switch 漏 `break` 静默 fall-through；switch 表达式漏分支编译报错
- `while` 先判断，`do-while` 后判断
- `break` 只跳一层，用标签跳多层
- 增强 for 改不了集合，删元素用 `removeIf`
- 三目运算符两分支类型不一致会提升到更宽的类型
