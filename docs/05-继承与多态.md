## 一、继承：把共同的部分提到父类

拿图形举例最清楚。圆和矩形都是图形，但它们算面积的算法完全不同。
如果调用方写的是 `shape.area()`，它既不用知道 `shape` 到底是圆还是矩形，
以后加了三角形也不用改一行代码。

```java
public abstract class Shape {

    protected final String name;            // 共有字段

    public String describe() {              // 具体方法：父类说了算
        return name + " 的面积是 " + String.format("%.2f", area());
    }

    public abstract double area();          // 抽象方法：子类必须补上
}
```

`Circle extends Shape` 一写，子类就直接拿到了 `name` 和 `describe()`：

```terminal
========== 3. 父类的具体方法，子类直接继承 ==========
圆 的面积是 3.14
矩形 的面积是 6.00
```

**代码复用是顺带的，真正值钱的是**：父类可以只面向"图形"编程，
不需要知道有哪些具体图形。这就是下一节的多态。

### 1.1 `protected` 是给子类留的门

第 04 课讲过 `private`（只有自己）、`public`（所有人）。`protected` 是第三种：

| 修饰符 | 谁能碰 |
|---|---|
| `private` | 只有这个类自己 |
| 不写（包私有） | 同包的类 |
| `protected` | 同包 + **所有子类** |
| `public` | 所有人 |

`Circle.toString()` 里直接用了父类的 `name`，没走 getter：

```java
@Override
public String toString() {
    return name + "(半径 " + radius + ")";   // 直接读父类的 protected 字段
}
```

### 1.2 子类构造器的第一句必须是 `super(...)`

```java
public Circle(double radius) {
    super("圆");          // 父类构造器先跑，所以这必须是第一句
    this.radius = radius;
}
```

写了 `super(...)` 之后，编译器就不再自动补无参的 `super()` 了。
所以**父类没有无参构造器时，子类必须显式调一次**。

## 二、重写：子类换一套实现

父类说"所有图形都得会算面积"，但没说怎么算——那是子类的活：

```java
@Override
public double area() {
    return Math.PI * radius * radius;
}
```

```terminal
========== 1. 向上转型：写子类，用父类接着 ==========
circle.area()    = 3.141592653589793   ← 调到了 Circle 的
rectangle.area() = 6.0   ← 调到了 Rectangle 的
两行写法一模一样，结果不同
```

`@Override` 不是必需的，但**建议总是写上**：它让编译器帮你检查方法名有没有拼错、
参数列表对不对。拼错了没这个注解，编译器一声不吭地当成新方法，
然后你会花很久去查"为什么父类那版还在跑"。

### 2.1 同名的 `static` 方法是隐藏，不是重写

这是第 04 课预告的那个点。看第 4 节的输出：

```java
Circle circle = new Circle(1);
Shape asShape = circle;          // 还是同一个对象

circle.kind()      // "circle"
asShape.kind()     // "shape"     ← 变量类型是 Shape，就调 Shape 的
```

```terminal
========== 4. 同名 static 方法是隐藏，不是重写 ==========
c.kind()        = circle   ← Circle 那个
asShape.kind()  = shape   ← Shape 那个！
但 asShape 里装的确实是个 Circle：true
换成实例方法就不一样：asShape.area() = 3.141592653589793
```

结果不同，而且 `asShape` 里装的**确实**是个 `Circle`（`asShape == c` 是 `true`）。
原因就是第 04 课那句话：

> **`static` 方法属于类，不属于对象。**

既然不属于对象，那"哪个对象调用它"就完全不影响结果——编译器在**编译期**
就按变量声明的类型定死了调哪个。运行期换成什么对象都没用。

对比一下 `area()`：它是实例方法，属于对象，所以按对象实际类型走——
这就是**重写**（overriding）。而 `kind()` 是**隐藏**（hiding），两者完全不同：

| | 绑定时机 | 依据 | 术语 |
|---|---|---|---|
| 实例方法 | 运行期 | 对象的实际类型 | 重写 overriding |
| `static` 方法 | 编译期 | 变量声明的类型 | 隐藏 hiding |
| `private` 方法 | 编译期 | 变量声明的类型 | 也是隐藏 |
| 字段 | 编译期 | 变量声明的类型 | 也是隐藏 |

最后一行很多人不知道：**字段也不参加多态**。`Shape s = circle; s.name` 拿到的是
`Shape` 那个 `name`（本例里都是"圆"看不出来，但概念上要清楚）。

## 三、多态：同一个调用，不同的反应

```java
List<Shape> shapes = List.of(new Circle(1), new Rectangle(2, 3));
shapes.get(0).area()   // 3.14
shapes.get(1).area()   // 6.0
```

两行的写法**一模一样**，结果却不同。变量类型是 `Shape`，
但方法调用最终落到哪个实现，由那个对象自己决定。

于是调用方可以完全不提具体子类：

```java
public static double totalArea(List<Shape> shapes) {
    double sum = 0;
    for (Shape shape : shapes) {
        sum += shape.area();
    }
    return sum;
}
```

`totalArea` 里没有 `Circle`、没有 `Rectangle`，只有一个 `Shape`。
**这就是多态的实用价值**：新增一种图形时，只有新类要写，
用它的老代码一行都不用动。

本课的 `Triangle` 就是后加的，`totalArea` 一行没改就能算它。

父类的方法还能当模板用，输出由子类填：

```java
new Circle(1).describe()         // 圆 的面积是 3.14
new Rectangle(2, 3).describe()   // 矩形 的面积是 6.00
```

`describe()` 的格式只写在父类一处，两句的不同全来自 `name` 和 `area()`。

## 四、类型检查：向上、向下、`instanceof`

变量声明成什么类型，和对象实际是什么类型，是两件事。

| | 写法 | 什么时候检查 | 出错怎么办 |
|---|---|---|---|
| 向上转型 | `Shape s = new Circle(1)` | 编译期 | 编译期报错 |
| `instanceof` | `s instanceof Circle` | 运行期 | 返回 `false` |
| 向下转型 | `(Circle) s` | 运行期 | 抛 `ClassCastException` |

向上转型**隐式发生**，编译器确认 `Circle` 是 `Shape` 就放行：

```java
Shape asShape = new Circle(2);
asShape.area()   // 还是 Circle.area()，this 记着那个对象
```

想拿回子类才有的东西，就要显式强转：

```java
Circle backToCircle = (Circle) asShape;
backToCircle.radius()   // 2.0
```

强转**不创建新对象**，只是告诉编译器"你按 `Circle` 来理解它"。

### 4.1 转错了要到运行期才发现

编译器只知道 `asShape` 的类型是 `Shape`，没法知道里面装的是什么，
所以它放你过去；等真转的时候才检查：

```terminal
========== 6. 向下转型：转错了要到运行期才知道 ==========
ClassCastException: class Rectangle cannot be cast to class Circle
```

所以强转之前最好先问一句：

```java
if (asShape instanceof Circle c) {
    c.diameter();     // c 在这里已经是 Circle 类型
}
```

这是**模式匹配**（Java 16 起）。旧写法要先 `instanceof` 判断、再强转一次，
写成 `instanceof Circle c` 之后判断和取值一步做完，而且 `c` 的作用域只在
`if` 成立的那段里：

```java
for (Shape shape : shapes) {
    if (shape instanceof Rectangle r && r.width() > 2) {
        // && 短路：r.width() 只在真的是 Rectangle 时才执行
        totalWidth += r.width();
    }
}
```

## 五、抽象类与接口

`Shape` 前面那个 `abstract` 不是装饰。它表示**这个类不许直接造对象**：

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/basics/inheritance/broken/AbstractInstantiation.java
src/main/java/dev/javalearning/basics/inheritance/broken/AbstractInstantiation.java:7: error: Shape is abstract; cannot be instantiated
        Shape s = new Shape("圆");   // ← Shape 是抽象的
                  ^
1 error
```

**`Shape is abstract; cannot be instantiated`**——编译器直接挡住。
没有面积可言的图形不存在。而 `Circle` 和 `Rectangle` 各自补上了 `area()`，
就变成可以造的了。

顺便一提，写成匿名类也不行：

```terminal
$ javac -encoding UTF-8 -d out -sourcepath src/main/java \
    src/main/java/dev/javalearning/basics/inheritance/broken/AnonymousShape.java
src/main/java/dev/javalearning/basics/inheritance/broken/AnonymousShape.java:7: error: <anonymous dev.javalearning.basics.inheritance.broken.AnonymousShape$1> is not abstract and does not override abstract method area() in Shape
        Shape s = new Shape("圆") {};   // ← 匿名类，没实现 area()
                                 ^
1 error
```

匿名类也得把抽象方法补齐，否则一样编译不过。

**抽象指的是"造不出实例"，不是"什么都不许有"。** 构造器、具体方法、字段、
`static` 方法都照常有——上面那个 `describe()` 模板就是具体方法。

### 5.1 接口是一份"必须做到"的清单

抽象类是"是什么"，接口是"能做到什么"。接口的要点：

- 接口方法**不写修饰符**，但编译器会补上 `public abstract`
- 接口**不能有实例字段**（`static final` 的常量可以）
- `default` 方法给了现成的做法，实现者可以选择不重写

```java
public interface Describable {
    String name();                    // 抽象方法
    default String label() {          // 默认方法：有现成的做法
        return "<" + name() + ">";
    }
}
```

一个类只能继承一个父类（Java 不支持多继承），但**可以实现多个接口**。
这是接口存在的主要理由之一。

## 六、`equals` 与 `hashCode` 是一份契约

现在回到开头那个问题。

### 6.1 重写 `equals`：按内容比

```java
@Override
public boolean equals(Object other) {
    if (this == other) {
        return true;                    // ① 同一个对象，直接相等
    }
    if (!(other instanceof Money that)) {
        return false;                   // ② 类型不对就不等
    }
    return this.cents == that.cents;    // ③ 内容一样才算相等
}
```

三个步骤各管一件事：

| 写法 | 作用 |
|---|---|
| `this == other` | 同一个对象，直接相等，省掉后面的比较 |
| `other instanceof Money that` | 类型不对就不等，不用逐个排除别的类型 |
| `cents == that.cents` | 内容一样就算相等 |

```terminal
========== 8. equals 重写了，内容一样就算相等 ==========
a == b      → false
a.equals(b) → true
hashCode 相同吗 → true
Set 里放 3 个相同的 → 1 个
```

### 6.2 契约：`equals` 判相等，`hashCode` 必须一样

**这不是建议，是编译器不检查、但 `HashSet` / `HashMap` 依赖的约定。**

它们先按 `hashCode` 分桶，只在同一个桶里才调 `equals` 去比。所以：

> 两个对象如果 `equals` 判相等，它们的 `hashCode` **必须**一样。
> 反过来不要求——`hashCode` 一样只代表"可能在同一个桶"，还得靠 `equals` 确认。

契约成立时，三个金额相同的 `Money` 放进 `HashSet` 会合并成一个。
现在看破坏契约的后果——本课最精彩的一段：

```terminal
$ java src/test/java/dev/javalearning/basics/inheritance/broken/BrokenMoney.java
放进去 3 个相同的 100 分，HashSet 里剩 3 个
（正确的话应该剩 1 个）
```

`BrokenMoney` 只重写了 `equals`，漏了 `hashCode`。它**编译通过、运行不报错**，
只是结果静默错误：

```
equals 说这三个相等，但 hashCode 各不相同
        ↓
落进三个不同的桶
        ↓
equals 根本没机会被调用
        ↓
集合里留下三份
```

这种 bug 比编译错误危险得多——没有报错，没有异常，只是数据莫名其妙多了一份。
所以**两个必须一起重写**。

至于这个反面教材为什么住在 `src/test` 而不是 `src/main` 的 `broken/` 包里：
因为 `broken/` 里的东西是**编译不过**的（会被构建排除），
而它编译得过、只是行为错，必须能被测试引用才能把错误钉住。

## 七、不推荐的用法

- **别为了复用代码而继承**。继承的正当理由是"是一个"（`Circle` **是** `Shape`），
  不是"想少写几行"。想复用请用组合：把对方当字段持有
- **别重写 `equals` 却漏掉 `hashCode`**。这是本课最贵的一课，见上面
- **别用 `==` 比对象内容**。第 01 课讲过 `String`，现在讲你自己写的类，规则一样
- **别对 `static` 方法用 `@Override`**。编译器会拦（`static` 方法不能被重写），
  但更重要的是理解"隐藏"和"重写"的区别
- **别把父类设计成"什么都能改"**。父类的改动会影响所有子类；
  如果子类行为依赖父类实现细节，加个新方法就可能悄悄破坏它
- **别做超过三层的继承链**。`A → B → C → D` 之后，想知道 `d.foo()` 到底跑哪段代码，
  你得把四个类都翻一遍

## 八、这一课的术语表

- **继承**（inheritance）—— 子类拿到父类的字段和方法，用 `extends`
- **父类 / 子类**（superclass / subclass）—— 也叫基类 / 派生类
- **重写**（overriding）—— 子类换掉继承来的**实例方法**实现，运行期按对象实际类型绑定
- **隐藏**（hiding）—— `static` 方法、`private` 方法、字段的"同名"行为，编译期按变量类型绑定
- **多态**（polymorphism）—— 同一个调用，不同对象给出不同行为
- **向上转型**（upcast）—— 子类赋给父类类型，隐式、编译期检查
- **向下转型**（downcast）—— 父类强转子类，显式、运行期检查，可能抛 `ClassCastException`
- **`instanceof` 模式匹配**—— `s instanceof Circle c`，判断和取值一步完成
- **抽象类**（abstract class）—— 不许直接造对象的类，可以有具体方法和字段
- **抽象方法**（abstract method）—— 只声明不实现，子类必须补上
- **接口**（interface）—— 一份"必须做到"的清单；一个类能实现多个
- **`default` 方法**—— 接口里带实现的方法，实现者可以不重写
- **`equals` / `hashCode` 契约**—— 两者必须一致，否则哈希集合会静默出错
- **组合**（composition）—— 把对方当字段持有，比继承更松的复用方式
