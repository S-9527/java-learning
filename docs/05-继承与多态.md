# 05 · 继承与多态

上一章把数据关进了类里。这一章要做一件更像「抽象」的事：
让一类东西**是**另一类东西，然后让同一个调用在不同对象上表现出不同的行为。

拿图形举例最清楚。圆和矩形都是图形，但它们算面积的算法完全不同。
如果调用方写的是 `shape.area()`，它既不用知道 `shape` 到底是圆还是矩形，
以后加了三角形也不用改一行代码——这就是多态。

主线是两步：**先把共同的部分提到父类，再让子类各自实现差异**。
中间会经过向上转型、向下转型和 `instanceof`，最后落到
`equals` / `hashCode` 这对容易被漏掉的方法上。

# 一、继承：把共同的部分提到父类

```java
// src: src/main/java/dev/javaquest/basics/inheritance/Shape.java
public abstract class Shape implements Describable {

    protected final String name;

    protected Shape(String name) {
        this.name = name;
    }

    public String describe() {              // 具体方法：父类说了算
        return name + " 的面积是 " + round(area());
    }

    public abstract double area();          // 抽象方法：子类必须补上
}
```

`Circle extends Shape` 一写，子类就直接拿到了 `describe()` 和 `name` 字段。
代码复用是顺带的——真正值钱的是**父类可以只面向「图形」编程，
不需要知道有哪些具体图形**。

### protected 是给子类留的门

上一章说过 `protected` 只在子类可见，这里就是它的用武之地：

```java
// src: src/main/java/dev/javaquest/basics/inheritance/Circle.java
@Override
public String toString() {
    return name + "(半径 " + radius + ")";   // 直接读父类的 name，不用调 getter
}
```

完整对照表在[第 04 章](04-变量与类型.md)，这里只记一句：
`private` 连子类都看不到，`protected` 把子类算作自己人，
不写修饰符则连子类也不给，只给同包的类。

### 子类的构造器第一句必须调 super

```java
public Circle(double radius) {
    super("圆");      // 父类构造器先跑，所以这必须是第一句
    this.radius = radius;
}
```

写了 `super(...)` 之后，编译器就不再自动补无参的 `super()` 了。
所以**父类没有无参构造器时，子类必须显式调一次**。

对应测试：子类对象能直接用父类的具体方法；super(...) 的参数决定了父类的字段；
protected 字段子类能直接读。

# 二、重写：子类换一套实现

父类说「所有图形都得会算面积」，但没说怎么算——那是子类的活。

```java
// src: src/main/java/dev/javaquest/basics/inheritance/Circle.java
@Override
public double area() {
    return Math.PI * radius * radius;
}
```

`@Override` 不是必需的，但建议总是写上：它让编译器帮你检查方法名有没有拼错、
参数列表对不对。拼错了没有这个注解，编译器一声不吭地当成新方法，
然后你会花很久去查「为什么父类那版还在跑」。

签名必须和父类**完全一致**——参数列表一样、返回类型一样。

参数列表不一样就变成重载了，那是另一个方法（第 03 章讲过）。
只改返回类型则会被编译器拦下，两种情况都有明确提示：

```text
f() in C cannot override f() in P        ← 实例方法
s() in C cannot hide s() in P            ← static 方法
return type int is not compatible with String
```

### 同名的 static 方法是隐藏，不是重写

这一点最容易想错，所以专门留着：

```java
// src: src/main/java/dev/javaquest/basics/inheritance/Shape.java
public static String kind() { return "shape"; }

// src: src/main/java/dev/javaquest/basics/inheritance/Circle.java
public static String kind() { return "circle"; }
```

写一个 Circle 对象，换个类型看它：

```java
Circle circle = new Circle(1);
Shape asShape = circle;      // 还是同一个对象

circle.kind()      // "circle"
asShape.kind()     // "shape"
```

结果不同，而且 `asShape` 里装的确实是个 `Circle`。原因是
**`static` 方法属于类，不属于对象**——编译期就按变量声明的类型定死了调哪个，
运行期换成什么对象都不影响。

这是第 04 章那句话的延续：`static` 成员装的是**一个值**，
归属是**类**。既然不属于对象，自然也不参加多态。

对应测试：子类重写之后调用到的是子类的实现；同名 static 方法是隐藏，不是重写。

# 三、多态：同一个调用，不同的反应

现在把不同的子类放进同一个容器：

```java
// src: src/main/java/dev/javaquest/basics/inheritance/ShapeDemo.java
List<Shape> shapes = List.of(new Circle(1), new Rectangle(2, 3));

shapes.get(0).area()   // 3.14
shapes.get(1).area()   // 6.0
```

两行的写法**一模一样**，结果却不同。变量类型是 `Shape`，
但方法调用最终落到哪个实现，由那个对象自己决定。

于是调用方可以完全不提具体子类：

```java
// src: src/main/java/dev/javaquest/basics/inheritance/ShapeDemo.java
public static double totalArea(List<Shape> shapes) {
    double sum = 0;
    for (Shape shape : shapes) {
        sum += shape.area();
    }
    return sum;
}
```

`totalArea` 里没有 `Circle`、没有 `Rectangle`，只有一个 `Shape`。
**这就是多态的实用价值**：新增一种图形时，只有新类要写，
用它的老代码一行都不用动。

父类的方法还能当模板用，输出由子类填：

```java
new Circle(1).describe()      // 圆 的面积是 3.14
new Rectangle(2, 3).describe()   // 矩形 的面积是 6.0
```

`describe()` 的格式只写在父类一处，两句的不同全来自 `name` 和 `area()`。

对应测试：同一个调用，不同的子类给出不同的结果；调用方不需要知道具体类型；
父类的方法模板可以被不同子类填出不同文字。

# 四、类型检查：向上、向下、instanceof

变量声明成什么类型，和对象实际是什么类型，是两件事。

| | 写法 | 什么时候检查 | 出错怎么办 |
|---|---|---|---|
| 向上转型 | `Shape s = new Circle(1)` | 编译期 | 编译期报错 |
| `instanceof` | `s instanceof Circle` | 运行期 | 返回 `false` |
| 向下转型 | `(Circle) s` | 运行期 | 抛 `ClassCastException` |

向上转型**隐式发生**，编译器确认 `Circle` 是 `Shape` 就放行：

```java
Shape asShape = new Circle(2);
asShape.area()   // 还是 Circle.area()，this 记着那个对象
```

想拿回子类才有的东西，就要显式强转：

```java
Circle backToCircle = (Circle) asShape;
backToCircle.getRadius()   // 2.0
```

强转**不创建新对象**，只是告诉编译器「你按 `Circle` 来理解它」。

### 转错了要到运行期才发现

编译器只知道 `asShape` 的类型是 `Shape`，没法知道里面装的是什么，
所以它放你过去；等真转的时候才检查：

```java
Shape rectangle = new Rectangle(2, 3);
Circle wrong = (Circle) rectangle;   // ClassCastException
```

所以强转之前最好先问一句：

```java
if (asShape instanceof Circle c) {
    c.getRadius();     // c 在这里已经是 Circle 类型
}
```

这是**模式匹配**（Java 16 起）。旧写法要先 `instanceof` 判断、再强转一次，
写成 `instanceof Circle c` 之后判断和取值一步做完，而且 `c` 的作用域只在
`if` 成立的那段里：

```java
for (Shape shape : shapes) {
    if (shape instanceof Rectangle r && r.getWidth() > 2) {
        // && 短路：r.getWidth() 只在真的是 Rectangle 时才执行
        totalWidth += r.getWidth();
    }
}
```

对应测试：向上转型是隐式的；`instanceof` 看的是实际装的什么对象；
`instanceof` 加上模式匹配；向下转型要显式写出来；
转错的类型在运行期抛 `ClassCastException`。
这一节对应练习 1（静态方法按声明类型绑定）和练习 2（转错类型会怎样）。

# 五、抽象类与接口：规定必须做什么

`Shape` 前面那个 `abstract` 不是装饰。它表示**这个类不许直接造对象**：

```java
new Shape("圆")   // 编译报错
```

没有面积可言的图形不存在，编译器直接挡住。
而 `Circle` 和 `Rectangle` 各自补上了 `area()`，就变成可以造的了。

抽象指的是「造不出实例」，**不是「什么都不许有」**。
构造器、具体方法、字段、`static` 方法都照常有——
上一节那个 `describe()` 模板就是具体方法。

### 接口是一份「必须做到」的清单

```java
// src: src/main/java/dev/javaquest/basics/inheritance/Describable.java
public interface Describable {

    String name();                    // 抽象方法

    default String label() {          // 默认方法：有现成的做法
        return "<" + name() + ">";
    }
}
```

三点值得记住：

- 接口方法**不写修饰符**，但编译器会补上 `public abstract`。
  不写不代表没有——`public` 是必须的，否则类外的代码调不到
- 接口**不能有实例字段**（`static final` 的常量可以）
- `default` 方法给了现成的做法，实现者可以选择不重写，也可以重写

```java
new Rectangle(2, 3).label()   // "<矩形>"，用的是接口那份
new Circle(1).label()         // "圆(1.0)"，Circle 自己重写了
```

同一个方法，两个类表现出不同行为——这也是多态。

对应测试：抽象类不能直接造对象；抽象类照样有构造器和具体方法；
接口里的方法隐式是 `public abstract`；`default` 方法不重写也能用；
重写 `default` 方法是可选的。
这一节对应练习 5：两个类的 `label()` 分别输出什么。

# 六、重写 Object 的方法：equals、hashCode、toString

第 04 章说没重写 `equals` 时比的是身份。现在把它写对。

```java
// src: src/main/java/dev/javaquest/basics/inheritance/Money.java
@Override
public boolean equals(Object other) {
    if (this == other) {
        return true;
    }
    if (!(other instanceof Money that)) {   // 模式匹配用在 equals 里很常见
        return false;
    }
    return this.cents == that.cents;
}

@Override
public int hashCode() {
    return Integer.hashCode(cents);
}
```

三个步骤各管一件事：

| 写法 | 作用 |
|---|---|
| `this == other` | 同一个对象，直接相等，省掉后面的比较 |
| `other instanceof Money that` | 类型不对就不等，不用逐个排除别的类型 |
| `cents == that.cents` | 内容一样就算相等 |

### hashCode 和 equals 是一份契约

**`equals` 判相等的两个对象，`hashCode` 必须一样。** 这不是建议，是编译器
不检查、但 `HashSet`、`HashMap` 依赖的约定：它们先按 `hashCode` 分桶，
只在同一个桶里才调 `equals` 去比。

契约成立时，两个金额相同的 `Money` 放进 `HashSet` 会合并成一个。
只重写 `equals` 而漏掉 `hashCode`，两个对象的 `hashCode` 各不相同，
落进不同的桶——`equals` 根本没机会被调用，集合里就留下了两份。

顺带一提，`toString` 也值得重写。第 04 章那个 `全类名@哈希值` 的默认输出，
在日志和异常信息里几乎没法看。

对应测试：重写 `equals` 之后内容相同就相等；`equals` 相等的对象 `hashCode` 必须一样；
契约成立 `HashSet` 才能去重；重写 `toString` 让输出可读。
这一节对应练习 3（默认 `equals` 仍比身份）和练习 4（只重写 `equals` 会剩几个）。

## 本章要点

- **继承的实用价值不是复用代码，而是让父类可以只面向自己编程**：
  新增子类时，用它的老代码一行都不用改
- 子类构造器的第一句必须是 `super(...)`；`@Override` 建议总是写，
  编译器会帮你抓拼错
- **`static` 方法属于类、不属于对象，不参加多态**：
  同名 static 方法是隐藏，按变量声明的类型绑定
- 向上转型隐式且编译期检查，向下转型显式且**运行期**才检查——
  所以强转前先 `instanceof Circle c` 这种模式匹配
- 抽象类不许造对象，但可以有构造器和具体方法；
  接口方法隐式 `public abstract`，`default` 方法可以重写也可以不重写
- **`equals` 与 `hashCode` 是一份契约**：两个必须一起重写，
  否则 `HashSet` 去重失效
